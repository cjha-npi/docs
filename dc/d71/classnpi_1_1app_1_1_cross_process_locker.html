npi::app::CrossProcessLocker Class Referencefinal

#include <CrossProcessLocker.hpp>

Description

Scoped owner of a session-local Windows named mutex.

Creates or opens a named mutex, waits indefinitely to acquire ownership, and releases ownership during destruction. The mutex name is prefixed with "Local\\", limiting synchronization to the current Windows session.

Copying and moving are disabled so that exactly one locker object owns and releases the acquired mutex handle.

WAIT_ABANDONED is treated as successful acquisition. In that case, wasAbandoned_() returns true so the caller can validate or repair the protected resource when necessary.

Warning
Invalid input or failure to create or acquire the mutex causes immediate application termination.

npi::app::CrossProcessLocker::CrossProcessLocker ( const QString & name)
inlineexplicit

Create or open a session-local named mutex and acquire it.

Parameters
nameLogical mutex name without "Local\\" and without backslashes. Example: "npi-SharedFileLock".

Internally, the name is converted to UTF-16 and prefixed with "Local\\". This constructor: 1) Calls CreateMutexW(nullptr, FALSE, L"Local\{name}"). Passing FALSE means the mutex is not acquired at creation time. 2) If the handle is valid, calls WaitForSingleObject(h, INFINITE). On WAIT_OBJECT_0 or WAIT_ABANDONED, the lock is considered acquired. If another thread/process already owns the mutex, this call blocks until it becomes available.
