# html-output:
# ---------------------------------------------------------------------------
# HTML_OUTPUT sets the folder for generated HTML files. If the path is relative,
# Doxygen places it under OUTPUT_DIRECTORY. If OUTPUT_DIRECTORY is empty, the
# path is relative to the directory from which Doxygen is started.
# inline-simple-structs:
# ---------------------------------------------------------------------------
# INLINE_SIMPLE_STRUCTS shows simple structs, classes, and unions inline in the
# documentation of their containing scope, such as a file, namespace, or group.
# If set to NO, they are shown on separate pages or sections.
#
# This can cause generated hash fragments to contain '/' characters,
# which can make jQuery/Sizzle throw:
# "Syntax error, unrecognized expression: #d5/d42/..."
# A fix for this has been implemented in doxy-plus.js.
# exclude-symbols:
# ---------------------------------------------------------------------------
# EXCLUDE_SYMBOLS excludes matching symbols from the generated output.
# With EXTRACT_ALL = YES, Doxygen can create mostly empty entries for external
# Qt classes when project classes inherit from them. We keep EXTRACT_ALL enabled
# and explicitly exclude the Qt classes that leak into the output.
# Do not use Q* here. It would also exclude project symbols whose names start
# with Q.
# image-path:
# ---------------------------------------------------------------------------
# IMAGE_PATH defines where Doxygen searches for images used by commands such as
# \image. The local "./_images" folder is for project images, and
# "E:/Doxy/_dev/_images" is for Dev Hub images.
# call-graphs:
# ---------------------------------------------------------------------------
# CALL_GRAPH and CALLER_GRAPH generate per-function call and caller graphs.
# In large C++/Qt projects, this can make documentation generation noticeably
# slower. Set both to NO for faster local/test documentation builds.
