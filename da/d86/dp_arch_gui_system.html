GUI System

Introduction

The GUI system provides a shared appearance and common behavior for the application's Qt Widgets interface. It supports dark, light and system-following themes, font-based sizing, custom drawing and optional widget features configured through dynamic properties. The system uses standard Qt widgets with a customized Fusion style. Application code controls it through npi::gui, without depending on the private implementation.

Reference Project: D146_Log_Gui

Final Evaluation Project: E131_GUI

Details

Gui.h provides the Public Interface containing:

  • Theme selection and queries.
  • Theme palettes and separate surface background colors.
  • Dynamic property names in npi::gui::Props.

Gui.cpp contains the implementation. Its private GuiStyle class derives from QProxyStyle and uses Fusion as its base style. Drawing and behavior that are not customized are generally left to the base style. The main responsibilities are:

  • Widget setup: Apply dynamic properties, configure grouped and embedded widgets, initialize icons and install event filters.
  • Sizing: Calculate consistent control heights, icon sizes and spacing from font sizes.
  • Drawing: Provide custom backgrounds, indicators, control layouts, completion items and multi-level table headers.
  • Themes: Update the application palette, tooltip palette, Qt color scheme and theme-dependent icons.
  • Events: Handle property updates, wheel forwarding, new actions and child widgets.
  • Windows integration: Observe Windows application-theme changes while System mode is selected.

QApplication owns the installed GuiStyle. A shared QPointer<GuiStyle> tracks it so public GUI functions can reuse the same instance, including when an application stylesheet wraps the style.

Initialization

The GUI system initializes automatically. Application code does not construct GuiStyle or call its private setup functions. There are two initialization paths:

  1. Deferred startup: A startup callback schedules initialization, which runs when application events are processed after QApplication construction.
  2. Public function call: Calling any public function in npi::gui initializes the GUI if needed.

Both paths use the private guiStyle() accessor and reuse the same style instance.

#include <QApplication>

Call QCoreApplication::processEvents() immediately after constructing QApplication, before creating widgets. This processes pending events including deferred initialization for the GUI and other application structures. Without this explicit call or an earlier public GUI function call, deferred initialization normally runs when QApplication::exec() starts processing events.

Initialization Steps

  1. Loads the bundled JetBrains Mono fonts.
  2. Constructs GuiStyle, saving the application font and sizing data, creating both themes and loading control icons.
  3. Installs the style using QApplication::setStyle().
  4. Sets the application icon, applies the initial System theme and installs the native event filter.
Note
No GuiStyle object is created before QApplication exists or after shutdown has begun.

Notification

The GUI system itself does not provide a theme or background change signal. Whenever a dark/light background is applied, GuiStyle performs updates in the following order:

  1. Updates QApplication and QToolTip palettes.
  2. Updates all background-dependent dynamic icons.
  3. Updates app QStyleHints object's color scheme.

The QStyleHints object qApp->styleHints() emits a colorSchemeChanged(Qt::ColorScheme colorScheme) signal, where:

  • colorScheme == Qt::ColorScheme::Dark for dark background, and
  • colorScheme == Qt::ColorScheme::Light for light background.

Connect to this signal like this:

QObject::connect(qApp->styleHints(), &QStyleHints::colorSchemeChanged, ...);

Another way to receive background change notification is to listen to either QEvent::PaletteChange or QEvent::ApplicationPaletteChange.

Note
  • Qt::ColorScheme::Unknown is never set by GuiStyle and therefore should not be expected.
  • The background is applied during initialization and whenever the requested dark/light background differs from the current background.
Warning
  • Palette is changed before dynamic icons are updated, so palette-change events do not indicate that the background update is complete.
  • Palette can change for reasons other than a dark/light background change.
  • A never-shown top-level window may not receive QEvent::PaletteChange. Do not rely on this event to initialize its appearance.

Public Interface

The GUI system exposes the following properties, enum, struct, and functions through Gui.h.

Custom Properties

The constants in npi::gui::Props identify dynamic properties used to request special widget behavior.

  • Use the Constant value when calling setProperty() in C++.
  • Use the String name as the dynamic property name in Qt Designer.
  • Use the specified Type for the property value.
  • Set boolean properties to true to enable their behavior.
Note
  • Prefer to set the property before the widget is polished.
  • If needed, polish the widget manually using its style, for example widget->style()->polish(widget).
  • Removing a property does not necessarily undo changes made during polishing.
Warning
Properties whose names begin with npi_gui_private_ are reserved for internal use in Gui.cpp.

Usage Examples

These examples assume the GUI system is initialized, the required Qt headers and Gui.h are included, and parent is an existing parent widget. Each example is independent and runs in the GUI thread.

Selecting a theme and querying colors

Select the application theme, then query the configured theme and effective background.

npi::gui::setTheme(npi::gui::Theme::Dark);
const auto selectedTheme = npi::gui::theme();
const bool darkBackground = npi::gui::isDarkBackground();

For custom drawing, retrieve the current palette and surface colors.

const auto palette = npi::gui::palette();
const auto surfaces = npi::gui::surfaces();

To retrieve colors for a specific background without changing the selected theme:

const auto darkPalette = npi::gui::palette(true);
const auto lightSurfaces = npi::gui::surfaces(false);
Note
npi::gui::Theme::System follows Windows settings. Use npi::gui::isDarkBackground() to determine its effective dark/light background.
Receiving background-change notifications

For a widget with custom drawing, request a repaint when the application's color scheme changes.

QObject::connect(qApp->styleHints(), &QStyleHints::colorSchemeChanged,
widget, [widget](Qt::ColorScheme) {
widget->update();
});

The widget's drawing code can retrieve its colors through npi::gui::palette() and npi::gui::surfaces().

Note
Connecting does not notify the widget about the current background. Apply its initial appearance when setting it up. See Notification.
Assigning theme-dependent icons

Set an action's icon properties before adding it to a menu or toolbar.

auto* menu = new QMenu{parent};
auto* saveAction = new QAction{"Save", menu};
saveAction->setProperty(npi::gui::Props::IconName_, QString{"save"});
menu->addAction(saveAction);

For a checkable action, supply an On-state icon when needed.

auto* pauseAction = new QAction{"Pause", menu};
pauseAction->setCheckable(true);
pauseAction->setProperty(npi::gui::Props::IconName_, QString{"pause"});
pauseAction->setProperty(npi::gui::Props::IconOnName_, QString{"resume"});
menu->addAction(pauseAction);

A tool button can use the same action and its icons.

auto* toolButton = new QToolButton{parent};
toolButton->setDefaultAction(saveAction);
Note
These examples require the corresponding icon resources. See npi::gui::Props::IconName_ and npi::gui::Props::IconOnName_ in Public Interface for resource naming and lookup.
Configuring password entry

Set the property before the line edit is polished.

auto* passwordEdit = new QLineEdit{parent};
passwordEdit->setProperty(npi::gui::Props::PasswordLineEdit_, true);
passwordEdit->setPlaceholderText("Password");

The style sets password echo mode, adds a show/hide action and enables the clear button.

Warning
Removing the property does not restore the original configuration.
Creating a shared background

Place controls inside a base widget and select its background.

auto* base = new QWidget{parent};
base->setProperty(npi::gui::Props::SunkenBase_, true);
auto* layout = new QHBoxLayout{base};
layout->setContentsMargins(4, 4, 4, 4);
layout->setSpacing(0);
auto* lineEdit = new QLineEdit{base};
auto* comboBox = new QComboBox{base};
comboBox->addItems({"Option 1", "Option 2"});
layout->addWidget(lineEdit);
layout->addWidget(comboBox);

Use npi::gui::Props::RaisedBase_ instead of npi::gui::Props::SunkenBase_ for a raised background.

Note
Layout margins and spacing are chosen by the application; the GUI system does not set them.
Warning
Do not reparent these configured controls and reuse them as ordinary widgets outside the base.
Creating an exclusive button group

Make the buttons direct children of the base widget.

auto* base = new QWidget{parent};
base->setProperty(npi::gui::Props::ButtonGroupBase_, true);
auto* layout = new QHBoxLayout{base};
layout->setContentsMargins(4, 4, 4, 4);
layout->setSpacing(0);
auto* firstButton = new QPushButton{"First", base};
auto* secondButton = new QPushButton{"Second", base};
layout->addWidget(firstButton);
layout->addWidget(secondButton);
base->style()->polish(base);
firstButton->setChecked(true);

Polishing creates the exclusive group and makes the buttons checkable. The initial checked button is selected afterward.

Note
  • Buttons nested inside other child widgets are not included.
  • Also set npi::gui::Props::SunkenBase_ on the base for an exclusive group with a sunken background.
Installing widgets in an item view

Set npi::gui::Props::ItemViewWidget_ on the root widget before installing it. Its children are handled automatically.

auto* table = new QTableWidget{1, 1, parent};
auto* cellWidget = new QWidget;
cellWidget->setProperty(npi::gui::Props::ItemViewWidget_, true);
auto* layout = new QHBoxLayout{cellWidget};
layout->setContentsMargins(0, 0, 0, 0);
layout->setSpacing(0);
layout->addWidget(new QPushButton{"Edit", cellWidget});
layout->addWidget(new QPushButton{"Remove", cellWidget});
table->setCellWidget(0, 0, cellWidget);
Note
The same root-widget property is used with setItemWidget() and setIndexWidget().
Warning
Create a separate widget for each item. Do not reuse configured item-view widgets as ordinary widgets elsewhere.
Adding separator borders

For a line edit inside a configured shared base or item-view widget, add a right-side separator.

lineEdit->setProperty(npi::gui::Props::SepBorders_, QString{"R"});
lineEdit->update();

Use any combination of T, R, B and L to select the borders.

For a frame line, the property's presence requests inset ends; its string value is ignored.

auto* separator = new QFrame{parent};
separator->setFrameShape(QFrame::HLine);
separator->setProperty(npi::gui::Props::SepBorders_, QString{});
Note
Except for frame lines, separator borders require the control's separate background to be suppressed by grouped or item-view styling.
Displaying and updating a color

Set the initial color before the button is polished.

auto* colorButton = new QPushButton{parent};
colorButton->setProperty(npi::gui::Props::ButtonColorDisplay_, QColor{60, 140, 220, 128});

After polishing, change the property to update the displayed color. Repainting is automatic.

colorButton->setProperty(npi::gui::Props::ButtonColorDisplay_, QColor{220, 100, 60});
Note
Transparency is shown over a checkerboard background.
Warning
The button still accepts mouse clicks and emits clicked(). Leave that signal unconnected if the button is only a color display.
Forwarding wheel input to a parent

For a control inside a scrollable container, enable wheel forwarding before the control is polished.

auto* spinBox = new QSpinBox{parent};
spinBox->setProperty(npi::gui::Props::WheelToParent_, true);

Wheel input is forwarded to the control's parent instead of changing the control's value.

Note
Forwarding targets the immediate parent; it does not search for a scroll area. The original event is consumed even if the parent ignores it.

Application Fonts

Default Application Font

The GUI system keeps the application font provided by Qt and Windows. It does not select a custom application-wide font family. Control sizes are calculated from font sizes and metrics. Atkinson Hyperlegible fonts were evaluated, but their visual alignment and font-fallback behavior required additional adjustments. The default font was retained. The earlier fallback investigation is recorded in Bug: Font CacheOverflowException.

JetBrains Mono

JetBrains Mono is bundled for technical content that benefits from fixed-width alignment and clearly distinguishable characters, such as identifiers, serial numbers, hexadecimal values and code. During GUI initialization, the Regular, Bold, Italic and Bold-Italic variants are loaded from Qt resources. No separate Windows font installation is required. Loading the font makes it available to the application; individual widgets must select it. To use it, copy the widget's font and change its family name to "JetBrains Mono". This preserves the existing font size. Use the same family name when requesting bold or italic text. For example:

QFont font{widget->font()};
font.setFamily("JetBrains Mono");
font.setBold(true);
widget->setFont(font);
Note
  • The GUI system must be initialized before selecting the bundled font. A failed font load produces a warning.
  • JetBrains Mono text can appear slightly higher than the default application font. The style shifts it down by one pixel in its adjusted text-drawing paths and line-edit contents. Custom painting outside these paths may require its own alignment adjustment.

Maintenance

Keep public changes in Gui.h and implementation changes in Gui.cpp. When modifying the GUI system:

  • Public interface: Keep Gui.h and this page consistent when changing functions, properties or supported behavior.
  • Themes: Update colors through make::theme. Keep palette roles and separate surface colors consistent.
  • Background updates: Keep theme application centralized in applyTheme_. Preserve the palette, dynamic-icon and color-scheme update order, along with handling of requests made during an update.
  • Sizing: Prefer the existing font-based sizing helpers. Check related control heights, icon sizes and spacing when changing sizing rules.
  • Properties: Check initial polishing, children added later and runtime changes where supported. Do not assume removing a property restores the original configuration.
  • Resources: Keep resource paths consistent with the implementation. Check both dark/light icons, common fallback icons and bundled fonts.
  • Qt updates: Repeat the relevant checks in Testing after upgrading Qt, since the GUI system relies on Fusion drawing and Qt widget behavior.
Note
Test affected widgets as fresh instances, including their grouped and item-view configurations where applicable.

Bug: Font CacheOverflowException

Bug
GUI System: Font fallback CacheOverflowException
Note
This is a historical investigation from the earlier Atkinson application-font experiments with Qt 6.8. It is not a confirmed issue in Qt 6.12.0. The current GUI system retains the default application font and does not implement the experimental workarounds below.

Observed Behavior

When using Atkinson Hyperlegible as the application font, the first rendering of password-mask characters produced four CacheOverflowException messages in the debugger.

This happened when:

  • Entering text into a QLineEdit using QLineEdit::Password, or
  • Changing a populated line edit from Normal to Password echo mode.

The debugger reported the following message four times:

Exception thrown at 0x00007FF99B4F187A in E118_Main.exe:
Microsoft C++ exception: CacheOverflowException at memory location 0x00000099324F2CC0.

A noticeable initial delay accompanied the operation. The application continued normally afterward, and subsequent rendering did not reproduce the exceptions during that run.

Font Fallback

The tested Atkinson font did not contain U+25CF, BLACK CIRCLE, which was used for password masking. Rendering it required a fallback font.

Qt 6.8 changed the default Windows font backend from GDI to DirectWrite. The older GDI backend remained available through the fontengine=gdi platform option. See What's New in Qt 6.8.

The observed behavior was consistent with first-use work in the DirectWrite font-fallback path, but the exact internal cause was not established.

Experimental Workarounds:

Using the older GDI font backend

In the earlier experiment, selecting GDI avoided the observed exceptions.

Set the platform option before constructing QApplication:

qputenv("QT_QPA_PLATFORM", "windows:fontengine=gdi");
QApplication app{argc, argv};
Warning
Changing the font backend affects the entire application. Check rendering and font behavior rather than switching solely to hide handled debugger exceptions.
Triggering font fallback during startup

Render the missing character before showing the interface to move the first-use work into startup.

void warmUpFontFallback()
{
QImage image{32, 32, QImage::Format_ARGB32_Premultiplied};
image.fill(Qt::transparent);
QPainter painter{&image};
painter.setFont(qApp->font());
// Render U+25CF BLACK CIRCLE to trigger the relevant fallback.
painter.drawText(image.rect(), Qt::AlignCenter, QString{QChar{0x25CF}});
}

For this experiment, register and assign the Atkinson application font first. Call the function before triggering GUI initialization through processEvents() or a public npi::gui function.

An explicit fallback family can also be selected:

QFontDatabase::addApplicationFallbackFontFamily(QChar::Script_Common,"Segoe UI");
warmUpFontFallback();

Qt provides this fallback-family API from version 6.8. The selected family must be available. See QFontDatabase::addApplicationFallbackFontFamily.

Note
Warming up fallback moves the work earlier; it does not fix the underlying cause or cover every missing character.
Using a password-mask character present in the font

The tested Atkinson font contained U+2022, BULLET, but not U+25CF, BLACK CIRCLE. Selecting BULLET avoided fallback for this particular character.

The following experimental override could be placed in a proxy style:

int styleHint(
QStyle::StyleHint hint,
const QStyleOption* option = nullptr,
const QWidget* widget = nullptr,
QStyleHintReturn* returnData = nullptr) const override
{
if(hint == SH_LineEdit_PasswordCharacter)
return 0x2022; // U+2022 BULLET.
return QProxyStyle::styleHint(hint, option, widget, returnData);
}
Note
This override is not implemented in the current GuiStyle. It avoids one missing glyph, not font fallback in general.
Warning
These observations and workarounds belong to the earlier tested font and runtime configuration. Recheck them before applying them to another font or Qt version.
