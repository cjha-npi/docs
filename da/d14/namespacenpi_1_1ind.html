npi::ind Namespace Reference

Description

Strictly self-contained and application-independent utility code.

This namespace contains copy-ready utility code that is not tied to any application module, domain namespace, or project-specific code.

Copy-ready rule: Each file or file-pair in this namespace must be usable as a standalone unit so that it can be copied into other projects without modification or additional requirements. Code in this namespace may include only C++ standard library headers, Qt headers, Windows headers, and its own matching header in a source file.

  • Allowed includes:
    • C++ standard library headers
    • Qt headers
    • Windows headers
    • Its own matching header in a source file
  • Forbidden includes:
    • Any project-specific header
    • Any npi::app header
    • Any domain-specific npi header
    • Any other npi::ind header
Note
Use this namespace only for standalone utility code. Domain-specific code belongs in a dedicated namespace, such as npi::log.

std::wstring npi::ind::winErrorText ( DWORD errorCode)
inline

Converts Windows DWORD error code into format "<text> (Code <number>).".

The function uses FormatMessageW() with the system message table to retrieve the description associated with DWORD error code. Windows allocates the message buffer internally, and the function releases that buffer using LocalFree() before returning.

Windows system messages commonly contain trailing carriage returns, line feeds, spaces, or tabs. These trailing characters are removed so the returned text can be embedded cleanly into log messages, dialogs, and exception descriptions.

Parameters
errorCodeWindows system error code to convert. This is commonly the value captured from GetLastError() immediately after a failed Windows API call.
Returns
Returns std::wstring human-readable system message without trailing whitespace. If supplied code is 0 then it returns "No error (Code 0)." If no system message is available or if FormatMessageW() fails, it returns "Unknown error, FormatMessageW failed (Code <number>)."
Note
Call GetLastError() before invoking this function and store its result locally. Calling other Windows API functions first may overwrite the thread's last-error value.
