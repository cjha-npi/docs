CJ_SysGraphs.lua File

Introduction

CJ_SysGraphs_GenCpuBars.lua is the Rainmeter Lua script used to generate the CPU bar include file for the CJ_SysGraphs skin. The generated file is named CJ_SysGraphs_CpuBars.inc and is included by the main skin using Rainmeter's @Include directive.

The script exists because the number of CPU bars depends on the number of logical CPU threads available on the system. Instead of manually writing one measure and two meters for every CPU thread, this script generates the required Rainmeter sections automatically.

Compact

CJ_SysGraphs_GenCpuBars.lua is the Lua script used by Rainmeter to generate the per-logical-CPU bar sections for the skin.

The script reads the logical processor count from the NUMBER_OF_PROCESSORS environment variable and generates one CPU measure, one CPU bar meter, and one CPU text meter for each logical CPU thread. The generated content is written to CJ_SysGraphs_CpuBars.inc, which is included by CJ_SysGraphs.ini.

Before writing, the script compares the newly generated content with the existing include file. It writes the file and refreshes the skin only when the content has changed. This avoids unnecessary file writes and prevents repeated Rainmeter refresh loops.

Purpose

The script generates one complete CPU display block for each logical CPU thread.

For every logical CPU, it creates:

Generated section Purpose
MeasureCPU<n> Reads the usage value of one logical CPU thread.
MeterBarCPU<n> Displays the CPU usage as a vertical bar.
MeterTextCPU<n> Displays the logical CPU number as text over the bar.

For example, on a system with 8 logical CPU threads, the script generates 8 CPU measures, 8 CPU bar meters, and 8 CPU text meters.

Role in the Skin

The main skin file, CJ_SysGraphs.ini, controls the overall layout, colors, dimensions, RAM meters, taskbar positioning, text toggle behavior, and skin refresh logic.

This Lua script only handles the generated CPU-bar portion of the skin. Its output becomes part of the main skin through:

@Include=#CURRENTPATH#CJ_SysGraphs_CpuBars.inc

This keeps the main skin file smaller and avoids hardcoding a fixed number of CPU bars.

Initialization Flow

The script runs from the Initialize() function, which Rainmeter calls when the script measure is initialized. This normally happens when the skin is loaded or refreshed.

During initialization, the script:

  1. Reads the OutputFile option from the Rainmeter script measure.
  2. Converts the output path to an absolute Windows path.
  3. Reads the number of logical processors from the NUMBER_OF_PROCESSORS environment variable.
  4. Builds the generated Rainmeter text using BuildCpuBars().
  5. Reads the existing output file.
  6. Writes the file only if the generated content has changed.
  7. Refreshes the skin only after a successful write.

This avoids unnecessary skin refreshes when the generated include file is already up to date.

Output File

The script writes to:

CJ_SysGraphs_CpuBars.inc

The generated file starts with a warning header stating that it is generated automatically and should not be edited manually.

It also records the detected CPU core/thread count in a comment line:

; CPU Core Count: <count>

This makes the generated file easier to inspect when debugging.

CPU Count Detection

The script gets the logical CPU count from the Windows environment variable:

NUMBER_OF_PROCESSORS

This value normally represents logical CPU threads, not only physical CPU cores. For example, a 6-core CPU with 12 threads will usually produce 12 generated CPU bar blocks.

If the environment variable is missing or invalid, the script falls back to 1. This prevents generation failure and ensures that at least one CPU bar is created.

Generated CPU Measures

For each logical CPU thread, the script generates a Rainmeter Measure=CPU section.

Each measure uses:

Processor=<n>

where <n> is the logical CPU index starting from 1.

The measure also contains threshold-based color logic. Depending on the CPU usage value, the matching CPU bar color is changed to:

Usage range Color variable
Below #BarThresholdMin# #MinColor#
Between #BarThresholdMin# and #BarThresholdMax# #MidColor#
Above #BarThresholdMax# #MaxColor#

The generated measure uses DynamicVariables=1 because these threshold and color values are defined in the main skin and may change while the skin is running.

Generated CPU Bar Meters

For each CPU measure, the script generates one Meter=Bar section.

The bar meter:

  • Uses the matching MeasureCPU<n> as its data source.
  • Is positioned horizontally based on the CPU index.
  • Uses [BarWidth] for its width.
  • Uses [SkinHeight] for its height.
  • Uses #BackgroundColor# as its background.
  • Is hidden when [BarWidth] is 0.

The X position is calculated using:

X=((<index> * [BarWidthWithSep]))

where <index> starts from 0. This places each CPU bar after the previous one, including the configured separator width.

Generated CPU Text Meters

For each CPU bar, the script also generates one Meter=String section.

The text meter displays the logical CPU number over the corresponding bar. These text meters are placed in the TextMeter group so the main skin can update or control them together.

The text meter:

  • Shows the CPU index as text.
  • Is centered horizontally over its CPU bar.
  • Uses font settings from the main skin.
  • Uses #TxtColor# for the text color.
  • Uses #BackgroundColor# as its background.
  • Is hidden when CPU bars are disabled or when #ShowText# is 0.

This allows the main skin to toggle CPU number labels without regenerating the include file.

File Change Detection

Rainmeter reads @Include files only when the skin is loaded or refreshed. Because of this, the script refreshes the skin after writing a changed output file.

However, refreshing every time would create unnecessary reloads. To avoid this, the script first reads the current contents of CJ_SysGraphs_CpuBars.inc and compares it with the newly generated text.

If both are identical, the script exits immediately and does not refresh the skin.

Helper Functions

The script uses two small helper functions:

Function Purpose
ReadFile(path) Reads the full contents of an existing file. Returns an empty string if the file cannot be opened.
WriteFile(path, text) Writes the generated text to the output file. Returns true on success and false on failure.

If writing fails, the script prints an error message containing the output path.

Practical Benefit

This script makes the skin adapt automatically to different CPUs. A user with 4 logical CPU threads gets 4 CPU bar blocks, while a user with 16 logical CPU threads gets 16 CPU bar blocks.

Without this script, the skin would either need a fixed maximum number of CPU bars or require manual editing for each system. This generated include approach keeps the skin portable, cleaner, and easier to maintain.

-- The generated file is included by the main Rainmeter skin using @Include.
-- Rainmeter reads @Include files only when the skin is loaded/refreshed, so this
-- script refreshes the skin only when the generated file actually changes.
--
-- Use it in the Rainmeter skin as:
--
-- [GenerateCpuBars]
-- Measure=Script
-- ScriptFile=#CURRENTPATH#CJ_SysGraphs_GenCpuBars.lua
-- OutputFile=#CURRENTPATH#CJ_SysGraphs_CpuBars.inc
-- UpdateDivider=-1
--
-- @Include=#CURRENTPATH#CJ_SysGraphs_CpuBars.inc
--
-- ============================================================================
-- Called automatically by Rainmeter when this script measure is initialized.
-- This usually happens when the skin is loaded or refreshed.
function Initialize()
-- Read the OutputFile option from the Rainmeter script measure.
-- Example: OutputFile=#CURRENTPATH#CJ_SysGraphs_CpuBars.inc
local output_file = SELF:GetOption("OutputFile")
-- Convert the Rainmeter path to an absolute Windows path.
-- This allows io.open() to write to the correct file location.
output_file = SKIN:MakePathAbsolute(output_file)
-- Read the number of logical processors reported by Windows.
-- This is usually CPU threads, not necessarily physical CPU cores.
-- If the environment variable is missing or invalid, fall back to 1.
local cpu_count = tonumber(os.getenv("NUMBER_OF_PROCESSORS")) or 1
-- Build the full text that should be written to the generated include file.
local text = BuildCpuBars(cpu_count)
-- Read the existing generated file.
-- If the file already contains exactly the same text, nothing needs to be
-- written and the skin does not need to be refreshed.
local old_text = ReadFile(output_file)
if old_text == text then
return
end
-- Write the new generated text.
-- If writing succeeds, refresh the skin so Rainmeter re-reads the @Include
-- file and loads the newly generated sections.
if WriteFile(output_file, text) then
SKIN:Bang("!Refresh")
end
end
-- Builds the Rainmeter code for all CPU bars.
-- cpu_count:
-- Number of logical CPU threads for which sections should be generated.
-- returns:
-- A single string containing all generated Rainmeter sections.
function BuildCpuBars(cpu_count)
-- Store all generated lines in a table first.
-- This is better than repeatedly concatenating one large string.
local lines = {}
-- Header added to the generated file for clarity.
-- This also helps identify whether the file was generated by this script.
table.insert(lines, "; ============================================================================")
table.insert(lines, "; CJ_SysGraphs_CpuBars.inc")
table.insert(lines, "; Generated/Edited automatically by CJ_SysGraphs_GenCpuBars.lua.")
table.insert(lines, "; DO NOT EDIT MANUALLY!")
table.insert(lines, "; ============================================================================")
table.insert(lines, "")
table.insert(lines, "; CPU Core Count: " .. cpu_count)
table.insert(lines, "")
-- Generate one measure, one bar meter, and one text meter per CPU thread.
for ii = 1, cpu_count do
-- Rainmeter CPU processor indexes start at 1 for the first logical CPU.
-- Meter X positions start at 0, so the first bar uses index 0, the second
-- bar uses index 1, and so on.
local one_less = tostring(ii - 1)
-- ------------------------------------------------------------------------
-- CPU measure
-- ------------------------------------------------------------------------
table.insert(lines, "; ----------- Core " .. ii .. " -----------")
table.insert(lines, "[MeasureCPU" .. ii .. "]")
table.insert(lines, "Measure=CPU")
table.insert(lines, "Processor=" .. ii)
-- Set the bar color when CPU usage is below the minimum threshold.
table.insert(lines, "IfCondition=MeasureCPU" .. ii .. " < #BarThresholdMin#")
table.insert(lines, "IfTrueAction=[!SetOption MeterBarCPU" .. ii .. " BarColor \"#MinColor#\"][!UpdateMeter MeterBarCPU" .. ii .. "]")
-- Set the bar color when CPU usage is within the middle threshold range.
table.insert(lines, "IfCondition2=(MeasureCPU" .. ii .. " >= #BarThresholdMin#) && (MeasureCPU" .. ii .. " <= #BarThresholdMax#)")
table.insert(lines, "IfTrueAction2=[!SetOption MeterBarCPU" .. ii .. " BarColor \"#MidColor#\"][!UpdateMeter MeterBarCPU" .. ii .. "]")
-- Set the bar color when CPU usage is above the maximum threshold.
table.insert(lines, "IfCondition3=MeasureCPU" .. ii .. " > #BarThresholdMax#")
table.insert(lines, "IfTrueAction3=[!SetOption MeterBarCPU" .. ii .. " BarColor \"#MaxColor#\"][!UpdateMeter MeterBarCPU" .. ii .. "]")
-- Needed because this generated section uses Rainmeter variables such as
-- #BarThresholdMin#, #BarThresholdMax#, #MinColor#, #MidColor#, and #MaxColor#.
table.insert(lines, "DynamicVariables=1")
table.insert(lines, "")
-- ------------------------------------------------------------------------
-- CPU bar meter
-- ------------------------------------------------------------------------
table.insert(lines, "[MeterBarCPU" .. ii .. "]")
table.insert(lines, "Meter=Bar")
table.insert(lines, "AntiAlias=1")
table.insert(lines, "MeasureName=MeasureCPU" .. ii)
-- Position each bar after the previous one.
-- BarWidthWithSep already includes the bar width plus the separator.
table.insert(lines, "X=(" .. one_less .. " * [BarWidthWithSep])")
table.insert(lines, "Y=0")
-- Width and height are calculated by measures in the main skin.
table.insert(lines, "W=[BarWidth]")
table.insert(lines, "H=[SkinHeight]")
-- Background color behind the bar.
table.insert(lines, "SolidColor=#BackgroundColor#")
-- Hide the bar when CPU bars are disabled
table.insert(lines, "Hidden=(([BarWidth] = 0) ? 1 : 0)")
-- Needed because this meter uses section variables and normal variables.
table.insert(lines, "DynamicVariables=1")
table.insert(lines, "")
-- ------------------------------------------------------------------------
-- CPU text meter
-- ------------------------------------------------------------------------
table.insert(lines, "[MeterTextCPU" .. ii .. "]")
table.insert(lines, "Meter=String")
-- All CPU text meters are placed in one group so they can be updated or
-- controlled together from the main skin.
table.insert(lines, "Group=TextMeter")
table.insert(lines, "AntiAlias=1")
-- Center the text horizontally inside the corresponding CPU bar.
table.insert(lines, "X=((" .. one_less .. " * [BarWidthWithSep]) + ([BarWidth] / 2))")
table.insert(lines, "Y=#TextY#")
table.insert(lines, "W=[BarWidth]")
-- Text styling comes from the main skin variables.
table.insert(lines, "FontFace=#TextFont#")
table.insert(lines, "FontSize=#TextSize#")
table.insert(lines, "FontWeight=#TextWeight#")
-- Show the logical CPU index as the text.
table.insert(lines, "Text=" .. ii)
-- Center the text on the bar.
table.insert(lines, "StringAlign=Center")
-- Same background as the bar area.
table.insert(lines, "SolidColor=#BackgroundColor#")
table.insert(lines, "FontColor=#TxtColor#")
-- Hide the text when CPU bars are disabled or when the user toggles text
-- display off using ShowText.
table.insert(lines, "Hidden=((([BarWidth] = 0) || (#ShowText# = 0)) ? 1 : 0)")
-- Needed because this meter uses section variables and ShowText changes
-- dynamically while the skin is running.
table.insert(lines, "DynamicVariables=1")
table.insert(lines, "")
end
-- Convert the line table into one generated text block.
return table.concat(lines, "\n")
end
-- Reads a full file as text.
-- path:
-- Absolute path of the file to read.
-- returns:
-- The file contents, or an empty string if the file cannot be opened.
function ReadFile(path)
local file = io.open(path, "r")
if not file then
return ""
end
local text = file:read("*a")
file:close()
return text or ""
end
-- Writes text to a file.
-- path:
-- Absolute path of the file to write.
-- text:
-- Text content to write to the file.
-- returns:
-- true if writing succeeded, false otherwise.
function WriteFile(path, text)
local file = io.open(path, "w")
if not file then
print("Failed to write CPU bars include file: " .. path)
return false
end
file:write(text)
file:close()
return true
end
