3/**
4 * \file SlotGate.hpp
5 * \brief Provides scoped suppression of reentrant slot handling.
6 *
7 * This file defines the npi::ind::SlotGate class and the
8 * NPI_RETURN_IF_SLOT_BLOCKED macro.
9 *
10 * SlotGate can be used by GUI classes to prevent selected slot bodies from
11 * executing recursively or while programmatic widget updates are in progress.
12 * It does not prevent Qt from invoking a slot. Instead, the slot enters or
13 * checks the gate and returns without processing when the gate is already
14 * blocked.
15 *
16 * The implementation is not thread-safe. A SlotGate instance and every Blocker
17 * created from it must be accessed and destroyed on the same thread. This is
18 * suitable for QObject slots that execute exclusively on the GUI thread.
19 */
20

26/**
27 * \brief Enters a slot gate or returns from the current function when the gate
28 * is already blocked.
29 *
30 * The macro creates a local blocker that remains alive until the surrounding
31 * scope ends. If the specified gate is already blocked, the current function
32 * returns immediately.
33 *
34 * This macro is intended for void functions and should normally be placed once
35 * at the beginning of a function body. It expands to multiple statements and
36 * therefore must not be used as an unbraced control-statement body.
37 *
38 * \param gate SlotGate object to enter.
39 */
40#define NPI_RETURN_IF_SLOT_BLOCKED(gate) \
41 auto slotGateBlocker = (gate).tryEnter_(); \
42 if(!slotGateBlocker) \
43 return

47 /**
48 * \brief Controls scoped suppression of reentrant or unwanted slot handling.
49 *
50 * SlotGate maintains an internal blocking count. Each active Blocker
51 * increments this count when created and decrements it when destroyed. The
52 * gate remains blocked while at least one associated Blocker exists.
53 *
54 * block_() always creates an additional Blocker and therefore supports nested
55 * blocking scopes. tryEnter_() creates a Blocker only when the gate is
56 * currently unblocked, allowing only the first or outermost invocation to
57 * proceed.
58 *
59 * A SlotGate must outlive every Blocker created from it. A typical use is to
60 * store SlotGate as a member of a GUI class and use Blocker objects only as
61 * local variables inside that class's member functions.
62 *
63 * This class is not thread-safe and is intended for single-threaded use,
64 * particularly on the Qt GUI thread.
65 */

67 public:
68 /**

70 *
71 * A Blocker increments the associated gate's blocking count during

75 * can be stored in std::optional and returned from tryEnter_(). A moved-from
76 * Blocker becomes inactive and does not modify the count when destroyed.
