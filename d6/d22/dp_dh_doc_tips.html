Doc Tips

This page collects formatting techniques for Doxygen documentation, including Markdown, Doxygen commands and supported HTML. Most examples can be used in both Markdown pages and documentation comments in source files. Features using dp- classes depend on the custom doxy-plus.css stylesheet.

Add Links

The basic Markdown link syntax is:

[visible text](target)

For normal external links:

[Doxygen configuration manual](https://www.doxygen.nl/manual/config.html)

For Doxygen documentation pages, prefer \ref when linking to a page ID:

See \ref dp_doxyfile_full_code for the full file content.

With custom link text:

See \ref dp_doxyfile_full_code "Doxyfile full code".

More examples:

[Open Doxygen manual](https://www.doxygen.nl/manual/index.html)
[Open another Markdown file](other-file.md)
[Open a file in another folder](../docs/other-file.md)
[Go to a section in this file](#main-files)
[Go to a section in another file](other-file.md#main-files)

Add Images

Images can be inserted in Markdown pages using the standard Markdown image syntax:

![Image caption](image-file-name.png)

Recommended setup:

  1. Create an _images/ folder at the root.
  2. In Doxyfile, add the image folder to IMAGE_PATH:
    IMAGE_PATH = ./_images
  3. Copy the image file into _images/. Example:
    _images/test_img.png
  4. Reference the image from a Markdown file:
    ![Image caption](test_img.png)

If needed, an explicit relative path can also be used:

![Image caption](_images/test_img.png)

Width and height can also be adjusted as needed:

![Image caption](test_img.png){html: width=400px height=250px}
![Image caption](test_img.png){html: width=128px height=auto}
![Image caption](test_img.png){html: width=60% height=auto}
Warning
  • Keep image basenames globally unique across all IMAGE_PATH folders; otherwise, collisions can occur.
  • If you set both width and height, the browser may stretch/squash the image unless the ratio matches the original image.

Insert Anchors

Since we cannot add section ID to non-headings, to reference a non-heading part we can add an anchor like this:

Some text before.
\anchor dp_some_marker
This paragraph can now be referenced from somewhere else.

Reference it with:

See \ref dp_some_marker

With custom link text:

See \ref dp_some_marker "this specific point"
Note
Anchors follow the same rules as Section ID Prefix (see Additional Branches : Rules).

Force New Line

When we have a new line in the Markdown file, it does not always translate to new line in Doxygen generated output. Sometimes, we need to leave a gap line and that creates a new paragraph instead of just line break. To achieve line break use <br>, for example:

Line One.<br>
Line Two.

This will produce:
Line One.
Line Two.

Force Visual Indent

An indentation in Markdown file does not mean that Doxygen generated page will have the same indentation, to force an indent use HTML non-breaking space &nbsp;

Line One.<br>
&nbsp;&nbsp;Line Two.

This will produce output like:
Line One.
  Line Two.

Hide xrefitem Text at Source

When a Doxygen ALIASES based on \xrefitem is used (see Automatic Pages), Doxygen also shows the generated entry at the place where the alias is written.

For example, if the Markdown file contains:

\dh_bug Some text

the generated page shows the local BUG entry at that location:

This can sometimes be useful, but often it is not needed. To hide the local output, wrap the alias usage in an HTML element:

\htmlonly <div class="dp-hidden-xrefitem"> \endhtmlonly
\dh_bug Some text
\htmlonly </div> \endhtmlonly

This wraps the generated local output in an HTML div with the class dp-hidden-xrefitem. In doxy-plus.css, the following rule hides this class completely:

#doc-content > div > div.contents > div.textblock .dp-hidden-xrefitem {
display: none;
}

This removes the local output from the source page while still keeping the entry on the collected destination page, such as Dev Hub > Bugs List.

Add Line Gap

Text, especially numbered or bullet lists, may not show any visible gap between two items in the generated output from a Markdown file, no matter how many blank lines are placed between them. Sometimes additional separation is needed to make two items look visually separated. To add a visible gap, use:

<div class="dp-markdown-list-gap"></div>

For example:

- Point one
<div class="dp-markdown-list-gap"></div>
- Point Two

This creates a div with the class dp-markdown-list-gap between the two list items. In doxy-plus.css, the following rule assigns a height of one line to this item:

#doc-content > div > div.contents > div.textblock .dp-markdown-list-gap {
height: 1em;
}

Big Non-Heading Texts

To have bigger than normal texts in a Markdown file without creating a heading use (text can have spaces):

<span class="dp-markdown-big-text">Text</span>

This makes the text appear as:

Text

The generated text is wrapped in an HTML span with the class dp-markdown-big-text. In doxy-plus.css, the following rule changes the text appearance:

#doc-content > div > div.contents > div.textblock .dp-markdown-big-text {
font-size: 1.3em;
font-weight: 500;
}

Mid Non-Heading Texts

To have bigger than normal texts but smaller than Big Non-Heading Texts in a Markdown file without creating a heading use (text can have spaces):

<span class="dp-markdown-mid-text">Text</span>

This makes the text appear as:

Text

The generated text is wrapped in an HTML span with the class dp-markdown-mid-text. In doxy-plus.css, the following rule changes the text appearance:

#doc-content > div > div.contents > div.textblock .dp-markdown-mid-text {
font-size: 1.15em;
font-weight: 500;
}

Special Text Section

Creates a section with left border line. Section can include multiple paragraphs and Doxygen tags.

\htmlonly[block]
<div class="dp-markdown-section-text">
\endhtmlonly
Existing Markdown content goes here.
Multiple paragraphs, lists, tables and Doxygen notes can remain unchanged.
\htmlonly[block]
</div>
\endhtmlonly

The section will look like this:

Existing Markdown content goes here.

Multiple paragraphs, lists, tables and Doxygen notes can remain unchanged.

Note
This is a note

Expandable Details Section

Doxygen supports HTML <details> tag in Markdown pages. Inside this tag we can use the <summary> tag to show its heading.

<details>
<summary>Details Heading</summary>
Place the explanation here.
- First point.
- Second point.
\note Additional information.
```
void some_code_Text();
```
</details>

It will appear like this:

Details Heading

Place the explanation here.

  • First point.
  • Second point.
Note
Additional information.
void some_code_Text();

For a summary that ends with code, for example

<details>
<summary>`void someCode()`</summary>
Place the explanation here.
- First point.
- Second point.
\note Additional information.
```
void some_code_Text();
```
</details>

We can add class="ends-with-code" to summary, this makes sure that the end of the summary looks nice. So for example without class="ends-with-code" it will look like this

void someCode()

Place the explanation here.

  • First point.
  • Second point.
Note
Additional information.
void some_code_Text();

And with class="ends-with-code", that is, with this code:

<details>
<summary class="ends-with-code">`void someCode()`</summary>
Place the explanation here.
- First point.
- Second point.
\note Additional information.
```
void some_code_Text();
```
</details>

it will look like this:

void someCode()

Place the explanation here.

  • First point.
  • Second point.
Note
Additional information.
void some_code_Text();

Table Header Vertical Text

A table header can have vertical text using class dp-table-vertical on the th. For example:

<table>
<tr>
<th rowspan="5" class="dp-table-vertical">Vertical</th>
<th align="right">Row 1</th>
<td align="left">Row 1 details.</td>
</tr>
<tr>
<th align="right">Row 2</th>
<td align="left">Row 2 details.</td>
</tr>
<tr>
<th align="right">Row 3</th>
<td align="left">Row 3 details.</td>
</tr>
<tr>
<th align="right">Row 4</th>
<td align="left">Row 4 details.</td>
</tr>
<tr>
<th align="right">Row 5</th>
<td align="left">Row 5 details.</td>
</tr>
</table>

Produces:

VerticalRow 1Row 1 details.
Row 2Row 2 details.
Row 3Row 3 details.
Row 4Row 4 details.
Row 5Row 5 details.
Note
Set rowspan on the cell that spans the rows. Its value is the number of rows covered, including the row containing the cell. Do not add another cell for that column in the covered rows.

This is implemented through doxy-plus.css:

#doc-content table th.dp-table-vertical {
width: 32px;
font-size: 120%;
writing-mode: sideways-lr;
text-align: center;
vertical-align: middle;
white-space: nowrap;
border-bottom: none;
}
