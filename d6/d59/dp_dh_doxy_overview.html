Overview

Introduction

This page describes a custom Doxygen output generation setup. The main purpose of this setup is to make the generated documentation easier to navigate, easier to inspect, and better suited for large C++/Qt projects.

The generated documentation is based on standard Doxygen HTML output, but it is extended with:

  • JavaScript
  • CSS
  • XML
  • Header and footer HTML template modifications
  • Supporting external assets

The customization focuses on practical improvements such as:

  • improved navigation
  • custom page organization
  • integration of project-specific documentation pages
  • persistent project-specific browser storage
  • additional debug and inspection helpers
  • custom styling

The custom doxy-plus.js, doxy-plus.css and doxy-plus.xml files add an enhancement layer on top of Doxygen's generated pages without changing the documented source code itself.

Version Information

The current Doxygen output generation is built for the following versions:

  • Doxygen v1.16.1
  • Graphviz v14.1.5
  • Doxygen Awesome v2.4.2

Main Files

The custom Doxygen output generation setup is built from several files:

  1. Doxyfile : Contains the main Doxygen configuration
    • Define metadata, input & output locations
    • Configure HTML output, source browsing, diagrams and graphs, etc.
    • Reference custom HTML header/footer files
    • Include additional CSS, JavaScript, images, and external assets
    • Can be configured as double-click executable (see Dox Extension Setup)
    • Full file content: Doxyfile
  2. doxy-plus-head.html : Default Doxygen header with a few extra contents added.
    • Manipulate default widths of default Doxygen panes
    • Insert navigation panes
    • Added via HTML_HEADER tag in Doxyfile
    • Full file content: HTML Files
  3. doxy-plus-foot.html : Default Doxygen footer with a few extra contents added.
    • Insert JavaScript files
    • Added via HTML_FOOTER tag in Doxyfile
    • Full file content: HTML Files
  4. doxy-plus.js : Adds the custom behavior on top of the generated Doxygen HTML pages.
    • Build root and page navigation
    • Manage project-specific browser storage
    • Adjust search behavior
    • Expose debug and inspection helpers
    • Apply runtime layout updates
    • Added via HTML_EXTRA_FILES tag in Doxyfile
    • Full file content: doxy-plus.js
  5. doxy-plus.css : Adds the custom styling layer for the generated documentation.
    • Adjust colors for dark/light themes
    • Style navigation panes
    • Control dual-pane layout behavior
    • Adjust spacing around components
    • Improve responsive behavior
    • Style panels, buttons, and visual states
    • Added via HTML_EXTRA_STYLESHEET tag in Doxyfile
    • Full file content: doxy-plus.css
  6. doxy-plus.xml : Adds the custom page ordering for the generated documentation.
    • Moves the detailed description part to the top of the page
    • Added via LAYOUT_FILE tag in Doxyfile
    • Full file content: doxy-plus.xml
  7. Internal Assets: These files are generated internally.
    • npi_icon.png : The icon shown in browser tabs
      • Added via PROJECT_ICON tag in Doxyfile
    • npi_logo.png : The logo used in the HTML header.
      • Max size: H: 55px, W: 200px
      • Added via PROJECT_LOGO tag in Doxyfile
  8. External Assets: Free to use files downloaded from external sources.
    • Doxygen Awesome Theme
      • doxygen-awesome.css : Added via HTML_EXTRA_STYLESHEET tag in Doxyfile
      • doxygen-awesome-darkmode-toggle.js : Added via HTML_EXTRA_FILES tag in Doxyfile
    • store.js
      • store.everything.min.js : Added via HTML_EXTRA_FILES tag in Doxyfile
    • JetBrains Mono Font
      • JetBrainsMono-Regular.woff2 : Added via HTML_EXTRA_FILES tag in Doxyfile

Generation Flow

  1. Doxygen reads the project configuration from the Doxyfile.
  2. Doxygen processes the source files and Markdown documentation pages.
  3. The custom header and footer templates inject additional HTML, CSS, and JavaScript.
  4. Doxygen generates the default HTML output.
  5. doxy-plus.js enhances navigation, browser storage, page behavior, and debug helpers.
  6. doxy-plus.css modifies the layout and visual presentation.
  7. doxy-plus.xml changes the layout of the main HTML pages.

Browser Storage

The custom Doxy-Plus layer uses browser storage to preserve generated data, navigation state, and user-selected layout options. This reduces repeated processing and allows the generated documentation to keep a consistent browsing state. The following are the main types of data that are stored:

  • Last Purge Date: Helps remove expired data.
  • Generation Timestamp: Stores the Doxygen generation date and time. This helps detect a new documentation build and regenerate cached data when needed.
  • HTML and Hash Arrays: Store tree structures for HTML page links and page-local hash links.
  • Previous HTML: Stores the previously opened HTML page. This helps reopen the same page after a tab close or browser restart.
  • Page Vertical Scroll Position: Helps restore the previous vertical scroll position when a page is reopened.
  • Show/Hide States: Help restore user-selected visibility options.
  • Widths: Help restore user-selected pane widths.

Except for Last Purge Date, all other data is stored through store.js by doxy-plus.js. This provides two important features that are missing from plain browser storage:

  1. Namespace: Projects on the same origin share browser storage. This means that if two documentation outputs are hosted under the same origin, keys from one output can overwrite keys from another output. To avoid this, Doxy-Plus uses the store.js namespace feature, which prefixes stored keys with a namespace. The namespace is generated from the project base URL, usually the origin plus the documentation path, so different documentation outputs on the same origin can keep separate storage.
  2. Expiry: Browser storage does not provide a built-in mechanism to automatically remove stored data after a fixed expiry time. If a project is discontinued, moved, or renamed, old stored data may remain until it is manually cleared or removed by the browser. To avoid stale data accumulating indefinitely, Doxy-Plus uses the expiry feature from store.js. Each stored key is assigned an expiry time of 30 days. If the key is accessed before it expires, the expiry time is extended by another 30 days. Whenever a documentation page runs, Doxy-Plus checks the Last Purge Date. If the last purge was more than one day ago, it checks all Doxy-Plus storage keys on the current origin and removes keys whose expiry date is in the past. Only keys from the current origin can be checked, because browsers do not allow cross-origin storage access.

For keys that store large tree arrays, such as the HTML and hash arrays, the data is regenerated when a new Doxygen documentation build is detected using the Generation Timestamp. Otherwise, the previously stored tree arrays are reused.

Data & Navigation

The standard Doxygen output provides a single navigation tree for the generated documentation. This works, but it has three main drawbacks:

  1. Duplicate Nodes: Duplicate nodes increase the complexity of the navigation tree and can lead to situations such as phantom jumps, where clicking a node in one branch suddenly moves the user to a different branch.
  2. Hash Links: Mixing hash links with page URLs makes the tree harder to read and more difficult to navigate.
  3. Deep Nesting: The standard Doxygen navigation structure can be deeply nested. For example, opening a class page may require expanding multiple parent nodes before reaching the actual class documentation page. This becomes worse with nested namespaces.

Instead of using a single navigation structure, the Doxy-Plus layer uses a two-level navigation structure:

  1. Root Navigation: The root navigation data is derived from a clone of the standard Doxygen navigation data. This cloned data is then:

    • Pruned: Duplicate nodes and hash links are removed.
      • Eliminates phantom jumps.
      • Reduces complexity and size.
    • Reorganized: Nested lists are flattened and entries are moved into clearer branches.
      • Reduces deep nesting while preserving useful information.

    The pruned and reorganized data is displayed as the root navigation tree with additional layout enhancements from doxy-plus.css.

  2. Page Navigation: The page navigation data is a tree of hash links for the current page. This data is generated by doxy-plus.js and is completely independent of both the standard Doxygen navigation tree and the Doxy-Plus root navigation tree. The current HTML page is scanned for hash links, and a page-local tree is generated from the discovered links.

    This page navigation data is displayed as the page navigation tree with additional layout enhancements from doxy-plus.css.

Once generated, both root navigation data and page navigation data are saved for later reuse (see Browser Storage). By using a two-level navigation structure, the Doxy-Plus layer avoids the main drawbacks of the standard Doxygen navigation structure in the custom navigation view. The Doxy-Plus navigation structure is built separately from the standard Doxygen navigation structure, and users can switch between the two structures when needed.

Debug Helpers

Debug helpers are provided through the doxy-plus.js file. They expose important generated data, runtime data, and stored key-value pairs through the browser console.

On page load, one of the following messages is shown in the console:

● Full Reload: "dp" is the console debug handler

Or, if dp is already defined:

● Full Reload: "dp" already defined - "debugDoxyPlus" is the console debug handler

In normal cases, dp becomes the console debug handler. If dp is already defined, debugDoxyPlus is used instead.

The following debug data can be viewed through the console debug handler:

  • dp.about : Displays information about the generated documentation.
    • Date-Time: Doxygen generation date and time.
    • Doc Root: Origin URL plus the documentation path when hosted online, or the local folder path when opened offline.
    • Storage Namespace: Namespace used to store project data through the store.js namespace feature.
  • dp.build : Displays generated data for the current page.
    • dp.build.doxygen_navtree : Standard Doxygen navigation tree data.
    • dp.build.doxygen_navtree_pruned : Pruned Doxygen navigation tree data, with duplicate nodes and hash links removed.
    • dp.build.hash_data : Hash links / page navigation data for the current page.
    • dp.build.html_data : HTML links / root navigation data for the generated documentation.
    • dp.build.html_ignored : HTML pages deliberately ignored while generating dp.build.html_data.
    • dp.build.html_missed : HTML pages found in dp.build.doxygen_navtree_pruned but not in dp.build.html_data or dp.build.html_ignored.
    • dp.build.html_not_found : HTML pages expected by Doxy-Plus but not found in dp.build.doxygen_navtree_pruned.
  • dp.store : Displays stored key-value pairs.
    • dp.store.origin_storage : Displays all store.js key-value pairs stored on the current origin.
    • dp.store.project_storage : Displays all store.js key-value pairs stored for the current project.
    • dp.store.local_storage : Displays all key-value pairs stored in browser localStorage on the current origin.
    • dp.store.local_storage_non_store_js : Displays all key-value pairs stored in browser localStorage on the current origin without using store.js.
    • dp.store.session_storage : Displays all key-value pairs stored in browser sessionStorage.
    • dp.store.session_storage_non_store_js : Displays all key-value pairs stored in browser sessionStorage without using store.js.
    • dp.store.clear : Provides commands for clearing stored key-value pairs.
      • dp.store.clear.all : Clears all relevant stored key-value pairs.
      • dp.store.clear.local_storage : Clears key-value pairs from browser localStorage.
      • dp.store.clear.session_storage : Clears key-value pairs from browser sessionStorage.
      • dp.store.clear.origin_storage : Clears store.js key-value pairs on the current origin.
      • dp.store.clear.project_storage : Clears store.js key-value pairs for the current project only.
Note
For dp.store.clear... commands a popup will be shown on the main browser page asking for confirmation.

Tips & Tweaks

Dox Extension Setup

A Doxygen configuration file does not need to be named Doxyfile. Doxygen only cares about the file contents, not the file name or extension. For convenience, the configuration file can therefore be saved with a .dox extension and associated with Doxygen on Windows.

After the .dox extension association is configured:

  • Double-clicking a .dox file will run Doxygen using that file
  • Command Prompt window will automatically open and show details
  • Command Prompt window will automatically close after documentation generation is complete

This makes it extremely easy to run Doxygen generation. Below are the ways to configure, check and remove the .dox extension association on Windows.

Create Dox Extension Association

Keep the Doxygen configuration file contents unchanged, but save the file with a .dox extension. Then open Command Prompt as Administrator and run:

assoc .dox=Doxygen.Config

This associates all .dox files with the custom Doxygen.Config file type.

Configure Dox Extension Execution

In the Administrator level Command Prompt, if doxygen.exe is available through the PATH environment variable, then use:

ftype Doxygen.Config="%SystemRoot%\System32\cmd.exe" /d /c "for %%I in (%1) do pushd ""%%~dpI"" && doxygen ""%%~nxI"""

Else, if doxygen.exe is not available through PATH, use the full executable path instead. For example, if Doxygen is installed here C:\Program Files\doxygen\bin\doxygen.exe then use

ftype Doxygen.Config="%SystemRoot%\System32\cmd.exe" /d /c "for %%I in (%1) do pushd ""%%~dpI"" && C:\Progra~1\doxygen\bin\doxygen.exe ""%%~nxI"""

Check Dox Extension Association

To verify the .dox association, in an Administrator level Command Prompt, run:

assoc .dox
ftype Doxygen.Config

Remove Dox Extension Association

To revert the association, in an Administrator level Command Prompt, run:

assoc .dox=
ftype Doxygen.Config=

Create Taskbar Pinnable Shortcut

Since Microsoft’s current taskbar model is app-oriented, Windows may block pinning shortcuts whose target is not an .exe. To be able to pin the .dox file to the taskbar while maintaining its double-click to run functionality, do the following:

Create a Windows shortcut with following shortcut target

%SystemRoot%\System32\cmd.exe /d /c start "" "C:\Path\To\YourFile.dox"

Change C:\Path\To\YourFile.dox to the correct file. Then right-click the shortcut select Show more options > Pin to taskbar.

Bugs and Fixes

Broken Hash with INLINE_SIMPLE_STRUCTS

BUG
Doxygen Overview : Broken Hash with INLINE_SIMPLE_STRUCTS

In Doxyfile, the INLINE_SIMPLE_STRUCTS tag can be used to make simple POD-like structs appear inside the documentation of their parent file, namespace, group, class, or struct instead of being generated as separate documentation pages.

According to Doxygen:

When the INLINE_SIMPLE_STRUCTS tag is set to YES, structs, classes, and unions with only public data fields or simple typedef fields will be shown inline in the documentation of the scope in which they are defined (i.e. file, namespace, or group documentation), provided this scope is documented. If set to NO, structs, classes, and unions are shown on a separate page (for HTML and Man pages) or section (for LaTeX and RTF). The default value is: NO.

Doxygen generates HTML pathname for each struct, these HTML pathname contains forward slashes i.e. / (if CREATE_SUBDIRS = YES) and other characters that are valid HTML pathnames but not valid in a raw CSS id selector. When INLINE_SIMPLE_STRUCTS = YES, Doxygen uses the exact same HTML pathname as hash links, this causes jQuery/Sizzle to throw errors such as:

Syntax error, unrecognized expression: #d5/d42/...

The exception aborts the click handler and can break navigation, highlighting, and page-nav logic.

Associated GitHub Bug Report: Incorrect links in case of use INLINE_SIMPLE_STRUCTS (GitHub issue **#8596**)

To work around this broken hash-link problem, a patch has been implemented in doxy-plus.js, this patch has to be implemented at the top of the outermost IIFE:

; (function ($) {
'use strict';
// Patch jQuery to not throw when "#id" fragments contain CSS-invalid characters such as '/'.
(function () {
// Purpose
// Patch jQuery so that simple "#id" selectors created from Doxygen hash fragments do not throw.
// Doxygen (notably navtree.js) sometimes does $(hash) where hash comes from a link fragment.
// With some settings (e.g. INLINE_SIMPLE_STRUCTS=YES in doxyfile), those fragments can contain
// '/' and other characters that are not valid in a raw CSS id selector. jQuery/Sizzle then throws:
// "Syntax error, unrecognized expression: #d5/d42/..."
// The exception aborts the click handler and can break navigation/highlighting/page-nav logic.
//
// What this patch changes
// It monkey-patches jQuery's internal constructor $.fn.init (used by $()/jQuery()).
// For selectors that are a very simple "#something" (not complex CSS expressions), it escapes
// the id portion so that characters like '/' become '\/'. This makes the selector valid CSS,
// so jQuery returns an empty set instead of throwing.
//
// Scope and safety
// The patch is intentionally narrow:
// - Only touches selector strings that look like a simple "#id" (no spaces, combinators,
// attribute selectors, pseudo selectors, selector lists, etc.).
// - Does not change complex selectors to avoid altering legitimate query semantics.
// - Uses jQuery.escapeSelector when available (jQuery 3+), otherwise uses a conservative
// fallback escaping rule.
//
// Load order
// This code installs immediately if jQuery is already present. If not, it retries briefly
// using setInterval until jQuery loads, then patches once and stops retrying.
//
// Behavioral impact
// - Eliminates the "unrecognized expression" console errors for invalid hash-based selectors.
// - Prevents exceptions inside Doxygen handlers, allowing navigation logic to continue.
// - If the escaped id does not exist in the DOM, jQuery returns an empty set (normal behavior).
function escapeIdSelector(id) {
// Prefer jQuery's official escaper when present (jQuery 3+).
if (window.jQuery && typeof window.jQuery.escapeSelector === "function") {
return window.jQuery.escapeSelector(id);
}
// Fallback: escape anything that is not [A-Za-z0-9_-]
return String(id).replace(/[^a-zA-Z0-9_-]/g, function (ch) { return "\\" + ch; });
}
function patchOnce() {
var $ = window.jQuery;
if (!$ || !$.fn || !$.fn.init) return false;
if ($.fn.init.__doxyPlusPatched) return true;
var origInit = $.fn.init;
function isSimpleIdSelector(s) {
// Only rewrite very simple "#something" selectors.
// Do NOT touch complex selectors (spaces, combinators, attrs, pseudos, commas).
return typeof s === "string" &&
s.length >= 2 &&
s.charAt(0) === "#" &&
s.indexOf(" ") === -1 &&
s.indexOf(">") === -1 &&
s.indexOf("+") === -1 &&
s.indexOf("~") === -1 &&
s.indexOf(",") === -1 &&
s.indexOf("[") === -1 &&
s.indexOf(":") === -1;
}
var patchedInit = function (selector, context, root) {
if (isSimpleIdSelector(selector)) {
var rawId = selector.slice(1);
selector = "#" + escapeIdSelector(rawId);
}
return origInit.call(this, selector, context, root);
};
patchedInit.prototype = origInit.prototype;
patchedInit.__doxyPlusPatched = true;
$.fn.init = patchedInit;
return true;
}
// Install ASAP, even if our file loads before jquery.js.
if (patchOnce()) return;
var t = setInterval(function () { if (patchOnce()) clearInterval(t); }, 10);
})();
// ... Rest of the code
})(jQuery);
