Imp Log Process

Introduction

The npiImpLog.exe is a small background helper process. The purpose of this process is to keep important log writing separate from the main application process. Being a separate process, it can continue writing even when the main application is shutting down or has failed unexpectedly.

This process is intentionally simple. It does not own logging policy, formatting, filtering, rotation, or log configuration. Its main job is reliable byte transfer from standard input to a file. The main application sends log bytes through standard input, and this process appends those bytes to a log file.

Details

The main application starts npiImpLog.exe by passing the following command-line arguments:

  • argv[1] : Primary log file path.
  • argv[2] : Backup log file path (optional).

Both paths are expected to be complete drive-letter absolute file paths after path normalization, for example C:\Users\bla\file.log. Paths using forward slashes, such as C:/Users/bla/file.log, are normalized before validation. Relative paths, drive-relative paths, UNC paths, and directory paths are rejected.

Warning
The npiImpLog.exe performs only basic path normalization and validation. The caller is responsible for vetting the path policy before passing any file path, including whether the location is allowed, trusted, and appropriate.

The npiImpLog.exe process receives its data through an anonymous pipe connected to its standard input. Creating and managing this pipe is the responsibility of the main application. The npiImpLog.exe process will:

  • Normalize Paths: Forward slashes are converted to backslashes, so paths produced by Qt-style path handling can still be passed safely to Win32 file APIs.
  • Create Files and Parent Directories: On arrival of the first data, the process tries to open or create the primary log file. If that fails and a backup path was provided, it tries the backup log file. Missing parent directories are created as required.
  • Write Data in a Loop: Data read from standard input is written completely before the next input buffer is processed. If a partial write happens, the remaining bytes are written in a loop. While no input data is available, the process blocks on ReadFile() instead of polling, consuming almost no resource when idle.
  • Exit Automatically: The process exits normally when standard input reaches End-Of-File (EOF) or the input pipe is closed. The main application does not need to explicitly terminate npiImpLog.exe. Windows closes the main application's pipe handle during shutdown/crash; the npiImpLog.exe sees EOF/broken pipe and exits normally by itself. Before exiting normally, it flushes the file buffers and closes the log file handle.

Exit Codes

Return codes used by the process:

  • 0 : normal shutdown.
  • 1 : missing or invalid primary path argument.
  • 2 : primary path ends with a slash.
  • 3 : backup path ends with a slash.
  • 4 : missing or invalid standard input handle.
  • 5 : standard input read failed.
  • 6 : failed to open or create both primary and backup files.
  • 7 : failed to open or create primary file, and no backup was provided.
  • 8 : file write failed.
  • 9 : file write made no progress after repeated attempts.

Setup

Place npiImpLog.exe in the same directory as the main application EXE file.

Use the code below to start and communicate with the helper process. The function startProcess() should be called only once during application startup. The function write() sends data through the anonymous pipe to npiImpLog.exe, which then writes the data to the selected log file.

Warning
The code below assumes that npiImpLog.exe is located next to the main application EXE. It is not suitable as-is when placed inside a DLL and the helper executable is located next to that DLL. The call to GetModuleFileNameW(nullptr, ...) returns the process EXE path, not the DLL path.

/// \brief Converts a Win32 error code to a readable system error message.
/// \details
/// Uses `FormatMessageW()` to retrieve the Windows-provided message for the given
/// error code. Trailing whitespace and line breaks are removed from the result.
/// \param err Win32 error code, usually returned by `GetLastError()`.
/// \return Readable error message, or a fallback message if formatting fails.
std::wstring win32ErrorText(DWORD err)
{
if(err == 0)
return L"(no error)";
LPWSTR buf = nullptr;
constexpr DWORD flags = FORMAT_MESSAGE_ALLOCATE_BUFFER |
FORMAT_MESSAGE_FROM_SYSTEM |
FORMAT_MESSAGE_IGNORE_INSERTS;
// Ask Windows to allocate and fill the message buffer for this error code.
// The buffer must be released with LocalFree().
const DWORD len = ::FormatMessageW(
flags,
nullptr,
err,
MAKELANGID(LANG_NEUTRAL, SUBLANG_DEFAULT),
reinterpret_cast<LPWSTR>(&buf),
0,
nullptr);
std::wstring msg;
if(len != 0 && buf) {
msg.assign(buf, buf + len);
// FormatMessageW commonly appends CR/LF and spaces.
// Remove them so the text is safe to embed in one-line diagnostics.
while(!msg.empty() && (msg.back() == L'\r' || msg.back() == L'\n' || msg.back() == L' ' || msg.back() == L'\t'))
msg.pop_back();
}
else {
msg = L"(FormatMessageW failed)";
}
if(buf)
::LocalFree(buf);
return msg;
}

/// \brief Starts the important-log helper process.
/// \details
/// Creates an anonymous pipe, starts `npiImpLog.exe`, and connects the read end of
/// the pipe to the helper process standard input. The write end is kept by the
/// main process and later used by `write()`.
///
/// The helper process is started with restricted handle inheritance so only the
/// pipe read handle and the NUL output handle are inherited. This avoids leaking
/// unrelated inheritable handles into the child process.
///
/// \param primaryFullPath Primary log file path passed to `npiImpLog.exe`.
/// \param backupFullPath Optional backup log file path passed to `npiImpLog.exe`.
///
/// \pre This function expects `npiImpLog.exe` to be located in the same directory
/// as the main application executable. It retrieves the main executable's path using
/// `GetModuleFileNameW(nullptr, ...)`, where `nullptr` means the process EXE, and
/// constructs the helper's path accordingly. If the helper executable cannot be found
/// or launched, a fatal error dialog is shown and the process is terminated.
///
/// \note The function also performs a short startup wait to detect immediate helper
/// failure, such as invalid arguments, invalid standard input, or process startup failure.
///
/// \warning If this code is inside a DLL and the `npiImpLog.exe` is next to this DLL,
/// then `GetModuleFileNameW(nullptr, ...)` is wrong because `nullptr` here means the
/// process EXE, not the DLL.
void startProcess(const std::wstring& primaryFullPath, const std::wstring& backupFullPath)
{
if(hProcess != nullptr || hLogPipe != INVALID_HANDLE_VALUE)
return;
// GetModuleFileNameW(nullptr, ...) gets the full path of the currently running
// main executable, for example C:\MyApp\bin\MyApp.exe
wchar_t impLogExePathBuf[fileNameMaxLen]{};
const DWORD n = ::GetModuleFileNameW(nullptr, impLogExePathBuf, fileNameMaxLen);
if(n == 0 || n >= fileNameMaxLen) {
const DWORD err = ::GetLastError();
npi::app::winFatalMsg("Start Imp Log Process Failed",
QStringLiteral("'GetModuleFileNameW' Error: %1").arg(QString::fromStdWString(win32ErrorText(err))));
}
// Construct the helper executable path by replacing the main executable name with npiImpLog.exe.
std::wstring impLogExePath(impLogExePathBuf, impLogExePathBuf + n);
const size_t slash = impLogExePath.find_last_of(L"\\/");
if(slash == std::wstring::npos)
npi::app::winFatalMsg("Start Imp Log Process Failed", "npiImpLog.exe path could not be determined");
impLogExePath.resize(slash + 1);
impLogExePath += L"npiImpLog.exe";
// Create an inheritable anonymous pipe.
// Child (npiImpLog.exe) gets the read end as stdin.
// Parent (this process) keeps the write end for sending log data.
SECURITY_ATTRIBUTES sa{};
sa.nLength = sizeof(sa);
sa.bInheritHandle = TRUE;
HANDLE hRead = INVALID_HANDLE_VALUE; // read handle
HANDLE hWrite = INVALID_HANDLE_VALUE; // write handle
// Create the anonymous pipe with a reasonably large buffer to reduce the chance of blocking on writes.
constexpr DWORD pipeBufBytes = 256u * 1024u; // buffer 256 KiB
if(!::CreatePipe(&hRead, &hWrite, &sa, pipeBufBytes)) {
const DWORD err = ::GetLastError();
npi::app::winFatalMsg("Start Imp Log Process Failed",
QStringLiteral("'CreatePipe' Error: %1").arg(QString::fromStdWString(win32ErrorText(err))));
}
// Remove inheritance from the write handle. The child must inherit only
// the read end. If it inherits the write end too, EOF detection can
// break because the pipe would still have a writer open.
if(!::SetHandleInformation(hWrite, HANDLE_FLAG_INHERIT, 0)) {
const DWORD err = ::GetLastError();
::CloseHandle(hRead);
::CloseHandle(hWrite);
npi::app::winFatalMsg("Start Imp Log Process Failed",
QStringLiteral("'SetHandleInformation' Error: %1")
.arg(QString::fromStdWString(win32ErrorText(err))));
}
// The anonymous pipe is used only for the child process's standard input. The
// npiImpLog.exe does not use STDOUT or STDERR. Redirect both streams to NUL
// so the helper does not depend on the parent process having valid console handles,
// which is especially important for GUI applications.
// hNull is created as inheritable because it is explicitly passed to the child
// as STDOUT and STDERR. Unrelated inheritable handles are blocked later by the
// PROC_THREAD_ATTRIBUTE_HANDLE_LIST setup.
HANDLE hNull = ::CreateFileW(
L"NUL",
GENERIC_WRITE,
FILE_SHARE_READ | FILE_SHARE_WRITE,
&sa,
OPEN_EXISTING,
FILE_ATTRIBUTE_NORMAL,
nullptr);
// Check the NUL handle before starting the process.
if(hNull == INVALID_HANDLE_VALUE || hNull == nullptr) {
const DWORD err = ::GetLastError();
::CloseHandle(hRead);
::CloseHandle(hWrite);
npi::app::winFatalMsg("Start Imp Log Process Failed",
QStringLiteral("'CreateFileW(NUL)' Error: %1")
.arg(QString::fromStdWString(win32ErrorText(err))));
}
// Build command line in format: "npiImpLog.exe" "primary" "backup"
// Paths are quoted because both executable and log paths may contain spaces.
std::wstring cmdLine;
cmdLine.reserve(impLogExePath.size() + primaryFullPath.size() + backupFullPath.size() + 16);
cmdLine += L"\"";
cmdLine += impLogExePath;
cmdLine += L"\" \"";
cmdLine += primaryFullPath;
cmdLine += L"\"";
if(!backupFullPath.empty()) {
cmdLine += L" \"";
cmdLine += backupFullPath;
cmdLine += L"\"";
}
// Restrict inheritance to the exact handles needed by the child process.
HANDLE inheritList[2]{hRead, hNull};
// Ask Windows for the required memory size for one process/thread attribute.
// This first sizing call is expected to fail with ERROR_INSUFFICIENT_BUFFER
// and return the required byte count in attrListBytes.
SIZE_T attrListBytes = 0;
const BOOL attrSizeOk = ::InitializeProcThreadAttributeList(nullptr, 1, 0, &attrListBytes);
const DWORD attrSizeErr = ::GetLastError();
// For the sizing call, success is unexpected. The valid result is failure with
// ERROR_INSUFFICIENT_BUFFER and a non-zero attrListBytes value. Anything else
// means Windows did not provide a usable attribute-list size.
if(attrSizeOk || attrListBytes == 0 || attrSizeErr != ERROR_INSUFFICIENT_BUFFER) {
::CloseHandle(hNull);
::CloseHandle(hRead);
::CloseHandle(hWrite);
npi::app::winFatalMsg("Start Imp Log Process Failed",
QStringLiteral("'InitializeProcThreadAttributeList' (get size) Error: %1")
.arg(QString::fromStdWString(win32ErrorText(attrSizeErr))));
}
// Allocate the attribute-list buffer using the process heap because Windows
// owns the internal layout of this structure. It is later released with
// HeapFree().
auto* attrList = static_cast<LPPROC_THREAD_ATTRIBUTE_LIST>(
::HeapAlloc(::GetProcessHeap(), 0, attrListBytes));
if(!attrList) {
::CloseHandle(hNull);
::CloseHandle(hRead);
::CloseHandle(hWrite);
npi::app::winFatalMsg("Start Imp Log Process Failed", "'HeapAlloc' failed for attribute list");
}
// Initialize the allocated attribute list. This prepares the buffer so it can
// receive attributes such as the explicit handle inheritance list.
if(!::InitializeProcThreadAttributeList(attrList, 1, 0, &attrListBytes)) {
const DWORD err = ::GetLastError();
::HeapFree(::GetProcessHeap(), 0, attrList);
::CloseHandle(hNull);
::CloseHandle(hRead);
::CloseHandle(hWrite);
npi::app::winFatalMsg("Start Imp Log Process Failed",
QStringLiteral("'InitializeProcThreadAttributeList' Error: %1")
.arg(QString::fromStdWString(win32ErrorText(err))));
}
// Restrict child handle inheritance to hRead and hNull only. This prevents the
// child from inheriting unrelated handles, especially the pipe write handle.
if(!::UpdateProcThreadAttribute(
attrList,
0,
PROC_THREAD_ATTRIBUTE_HANDLE_LIST,
reinterpret_cast<void*>(inheritList),
sizeof(inheritList),
nullptr,
nullptr)) {
const DWORD err = ::GetLastError();
::DeleteProcThreadAttributeList(attrList);
::HeapFree(::GetProcessHeap(), 0, attrList);
::CloseHandle(hNull);
::CloseHandle(hRead);
::CloseHandle(hWrite);
npi::app::winFatalMsg("Start Imp Log Process Failed",
QStringLiteral("'UpdateProcThreadAttribute(HANDLE_LIST)' Error: %1")
.arg(QString::fromStdWString(win32ErrorText(err))));
}
// Configure the child standard handles. STDIN comes from the pipe read handle;
// STDOUT and STDERR go to NUL because the helper does not produce output.
STARTUPINFOEXW siex{};
siex.StartupInfo.cb = sizeof(STARTUPINFOEXW);
siex.StartupInfo.dwFlags = STARTF_USESTDHANDLES;
siex.StartupInfo.hStdInput = hRead;
siex.StartupInfo.hStdOutput = hNull;
siex.StartupInfo.hStdError = hNull;
siex.lpAttributeList = attrList;
// Receives the process and main-thread handles created by CreateProcessW().
PROCESS_INFORMATION pi{};
// CreateProcessW may modify the command-line buffer, so pass a mutable copy.
std::wstring mutableCmd = cmdLine;
// Start npiImpLog.exe with no window and with extended startup information.
// bInheritHandles must be TRUE because the handle list controls inheritance.
const BOOL ok = ::CreateProcessW(
impLogExePath.c_str(),
mutableCmd.data(),
nullptr,
nullptr,
TRUE, // must be TRUE when using HANDLE_LIST attribute
CREATE_NO_WINDOW | EXTENDED_STARTUPINFO_PRESENT,
nullptr,
nullptr,
&siex.StartupInfo,
&pi);
// Capture CreateProcessW failure immediately. Cleanup calls may overwrite the
// thread's last-error value.
const DWORD createProcErr = ok ? ERROR_SUCCESS : ::GetLastError();
// The attribute list is needed only during CreateProcessW. After the child is
// created or creation has failed, it can be destroyed and freed.
::DeleteProcThreadAttributeList(attrList);
::HeapFree(::GetProcessHeap(), 0, attrList);
if(!ok) {
::CloseHandle(hNull);
::CloseHandle(hRead);
::CloseHandle(hWrite);
npi::app::winFatalMsg("Start Imp Log Process Failed",
QStringLiteral("'CreateProcessW' Error: %1")
.arg(QString::fromStdWString(win32ErrorText(createProcErr))));
}
// The parent keeps only the child process handle and the pipe write handle.
// hRead and hNull belong only to the child side after process creation.
::CloseHandle(hNull);
::CloseHandle(hRead);
::CloseHandle(pi.hThread);
hProcess = pi.hProcess;
hLogPipe = hWrite;
// Detect immediate helper startup failure. In normal operation, the helper
// waits on STDIN and this short wait times out.
const DWORD waitResult = ::WaitForSingleObject(hProcess, 250);
if(waitResult == WAIT_FAILED) {
const DWORD err = ::GetLastError();
npi::app::winFatalMsg("Start Imp Log Process Failed",
QStringLiteral("'WaitForSingleObject' Error: %1")
.arg(QString::fromStdWString(win32ErrorText(err))));
}
// If the helper already exited, treat it as startup failure and report its
// npiImpLog-specific exit code.
if(waitResult == WAIT_OBJECT_0) {
DWORD code = 0;
(void)::GetExitCodeProcess(hProcess, &code);
npi::app::winFatalMsg("Start Imp Log Process Failed",
QStringLiteral("npiImpLog.exe returned %1: %2")
.arg(static_cast<qulonglong>(code))
.arg(processExitText(code)));
}
}
/// \brief Writes bytes to the important-log helper process.
/// \details
/// Writes raw bytes to the pipe connected to `npiImpLog.exe` standard input.
/// The function loops until all requested bytes are written or a failure occurs.
///
/// When `crash` is true, the function returns silently on write failure because it
/// may be executing during fatal-error handling where showing another fatal
/// message is unsafe or counterproductive.
///
/// When `crash` is false, repeated pipe write failure is reported with diagnostic
/// information, including the helper process exit code when available.
/// \param data Pointer to bytes that should be written.
/// \param len Number of bytes to write.
/// \param crash True when called from crash/fatal-path logging.
///
/// \warning Concurrent calls are not serialized by this function. Log records
/// may interleave in rare cases when multiple threads write at the same time.
/// This is intentional to avoid blocking or deadlocking in crash/fatal paths.
void write(const char* data, size_t len, bool crash)
{
// Nothing can be written unless the helper process and pipe are valid.
// Invalid input is treated as a no-op because logging must not destabilize
// the caller.
if(hProcess == nullptr ||
hLogPipe == nullptr ||
hLogPipe == INVALID_HANDLE_VALUE ||
data == nullptr ||
len == 0) {
return;
}
// Use a byte pointer so pointer arithmetic advances by exact byte count.
// remaining tracks how many bytes still need to be sent to the helper.
const unsigned char* bPtr = reinterpret_cast<const unsigned char*>(data);
size_t remaining = len;
// Counts repeated write attempts that made no progress.
// This prevents an infinite loop if the pipe stops accepting data.
int noProgressTries = 0;
while(remaining > 0) {
// WriteFile accepts a DWORD byte count, so very large writes are split into
// DWORD-sized chunks. Normal log writes will usually complete in one chunk.
const size_t chunkSz = (remaining > static_cast<size_t>(0xFFFFFFFFu))
? static_cast<size_t>(0xFFFFFFFFu)
: remaining;
const DWORD chunk = static_cast<DWORD>(chunkSz);
// Write the current chunk to the pipe connected to npiImpLog.exe STDIN.
// A successful call may still write fewer bytes than requested.
DWORD wrote = 0;
const BOOL ok = ::WriteFile(hLogPipe, bPtr, chunk, &wrote, nullptr);
if(!ok || wrote == 0) {
// GetLastError is meaningful only when WriteFile fails. If WriteFile
// succeeds but writes zero bytes, use a deterministic synthetic error.
const DWORD err = ok ? ERROR_WRITE_FAULT : ::GetLastError();
// During crash handling, do not show another fatal message or retry deeply.
// Best effort logging is safer than risking recursive failure handling.
if(crash)
return;
// Broken pipe errors mean the helper is gone, so retries are pointless.
// Other no-progress cases are retried briefly before reporting failure.
if(err == ERROR_BROKEN_PIPE || err == ERROR_NO_DATA) {
noProgressTries = 16;
}
else {
++noProgressTries;
}
// Give transient no-progress cases a few chances. This is intentionally
// short because blocking the main application on logging is worse.
if(noProgressTries < 16) {
::SwitchToThread();
continue;
}
// Build a diagnostic message containing the pipe write error.
// The helper process state is added below when available.
QString msg = QStringLiteral("WriteFile to npiImpLog pipe failed.");
msg += QStringLiteral("\nGetLastError %1: %2")
.arg(static_cast<qulonglong>(err))
.arg(QString::fromStdWString(win32ErrorText(err)));
// Broken pipe normally means npiImpLog.exe exited or failed during startup.
// This gives a clearer reason than the raw Win32 error alone.
if(err == ERROR_BROKEN_PIPE || err == ERROR_NO_DATA)
msg += QStringLiteral("\nPipe is closed. The helper likely exited or failed to start.");
// Add helper exit information if the process has already terminated.
// If it is still active, the pipe failure is reported as-is.
DWORD code = STILL_ACTIVE;
if(::GetExitCodeProcess(hProcess, &code)) {
if(code == STILL_ACTIVE) {
msg += QStringLiteral("\nHelper process is still running.");
}
else {
msg += QStringLiteral("\nHelper exited with code %1: %2")
.arg(static_cast<qulonglong>(code))
.arg(processExitText(code));
}
}
npi::app::winFatalMsg("Imp Log Write Failed", msg);
}
// Advance only after confirmed progress. Partial writes are handled by
// continuing the loop with the remaining unwritten bytes.
noProgressTries = 0;
bPtr += wrote;
remaining -= static_cast<size_t>(wrote);
}
}
}

/**
* \file npiImpLog.cpp
* \brief Background log writer executable.
* \details
* Reads bytes from standard input and appends them to a primary log file.
* If the primary file cannot be opened or created, an optional backup file is
* used instead. The helper normalizes path separators, creates missing parent
* directories, and keeps the write loop independent of the main application.
*
* Expected arguments:
* - argv[1]: primary log file path.
* - argv[2]: optional backup log file path.
*
* Return codes:
* - 0: Normal shutdown.
* - 1: Missing or invalid primary path argument.
* - 2: Primary path ends with a slash.
* - 3: Backup path ends with a slash.
* - 4: Missing or invalid standard input handle.
* - 5: Standard input read failed.
* - 6: Failed to open or create both primary and backup files.
* - 7: Failed to open or create primary file, and no backup was provided.
* - 8: File write failed.
* - 9: File write made no progress after repeated attempts.
*/
#define WIN32_LEAN_AND_MEAN
#define NOMINMAX
#include <windows.h>
#include <shlobj.h> // SHCreateDirectoryExW
#include <string>
#pragma comment(lib, "Shell32.lib")
/**
* \brief Helper functions for `npiImpLog.exe` path handling and file opening.
* \details
* These helpers intentionally implement only basic robustness:
* - convert Qt-style forward slashes to Windows backslashes,
* - reject directory-style file paths,
* - require drive-letter absolute paths,
* - create missing parent directories,
* - open files in append mode.
*/
namespace
{
/// \brief Converts a wide string file path to a Windows-style path.
/// \details
/// Returns an empty string when the input pointer is null. All forward slashes
/// are converted to backslashes so paths coming from Qt can be passed safely to
/// Win32 APIs.
/// \param filePath Null-terminated wide string file path.
/// \return Normalized file path.
std::wstring normalizedPath(const wchar_t* filePath)
{
if(filePath == nullptr)
return {};
std::wstring path(filePath);
for(wchar_t& ch : path) {
if(ch == L'/')
ch = L'\\';
}
return path;
}
/// \brief Checks whether a path ends with a path separator.
/// \details
/// Used to reject paths that clearly represent directories instead of files.
/// \param filePath File path to check.
/// \return True if the path ends with a backslash or forward slash.
bool endsWithSlash(const std::wstring& filePath)
{
if(filePath.empty())
return false;
const wchar_t last = filePath.back();
return last == L'\\' || last == L'/';
}
/// \brief Checks whether a character is an ASCII alphabetic drive letter.
/// \param ch Character to check.
/// \return True if the character is A-Z or a-z.
bool isAlphaDriveLetter(wchar_t ch) noexcept
{
return (ch >= L'A' && ch <= L'Z') || (ch >= L'a' && ch <= L'z');
}
/// \brief Checks whether a path uses drive-letter absolute syntax.
/// \details
/// Accepts paths like "C:\Logs\file.log". Rejects relative paths, UNC paths,
/// and drive-relative paths like "C:Logs\file.log".
/// \param filePath File path to check.
/// \return True if the path starts with "X:\".
bool isDriveAbsolutePath(const std::wstring& filePath)
{
return filePath.size() >= 3 &&
isAlphaDriveLetter(filePath[0]) &&
filePath[1] == L':' &&
filePath[2] == L'\\';
}
/// \brief Ensures that the parent directory of a file path exists.
/// \details
/// Requires a drive-letter absolute file path. If the parent directory already
/// exists, the function succeeds. If it does not exist, the full missing parent
/// directory chain is created using `SHCreateDirectoryExW()`.
/// \param filePath Drive-letter absolute file path.
/// \return True if the parent directory exists or was created successfully.
bool ensureParentDirExists(const std::wstring& filePath)
{
if(!isDriveAbsolutePath(filePath))
return false;
const size_t pos = filePath.find_last_of(L'\\');
if(pos == std::wstring::npos)
return false;
const std::wstring parentDir = filePath.substr(0, pos);
if(parentDir.empty())
return false;
// Example: "C:\file.log". Parent is drive root, nothing to create.
if(parentDir.size() == 2 && parentDir[1] == L':')
return true;
const DWORD attr = ::GetFileAttributesW(parentDir.c_str());
if(attr != INVALID_FILE_ATTRIBUTES)
return (attr & FILE_ATTRIBUTE_DIRECTORY) != 0;
const int rc = ::SHCreateDirectoryExW(nullptr, parentDir.c_str(), nullptr);
if(rc == ERROR_SUCCESS || rc == ERROR_ALREADY_EXISTS)
return true;
// Another process may have created the directory between the calls.
const DWORD attrAfter = ::GetFileAttributesW(parentDir.c_str());
return attrAfter != INVALID_FILE_ATTRIBUTES && (attrAfter & FILE_ATTRIBUTE_DIRECTORY) != 0;
}
/// \brief Opens a file for append-only writing.
/// \details
/// Uses `OPEN_ALWAYS` so the file is created if missing. The handle allows
/// other processes to read the file while this process writes to it.
/// \param filePath File path to open.
/// \return Valid file handle on success, `INVALID_HANDLE_VALUE` on failure.
HANDLE openAppendFile(const std::wstring& filePath)
{
return ::CreateFileW(
filePath.c_str(),
FILE_APPEND_DATA,
FILE_SHARE_READ,
nullptr,
OPEN_ALWAYS,
FILE_ATTRIBUTE_NORMAL,
nullptr);
}
/// \brief Opens a file for appending after ensuring its parent directory exists.
/// \details
/// The path is validated as a drive-letter absolute path before opening. Missing
/// parent directories are created before `CreateFileW()` is called.
/// \param filePath File path to open.
/// \return Valid file handle on success, `INVALID_HANDLE_VALUE` on failure.
HANDLE openAppendFileWithParentDir(const std::wstring& filePath)
{
if(!ensureParentDirExists(filePath))
return INVALID_HANDLE_VALUE;
return openAppendFile(filePath);
}
}
/// \brief Program entry point for the background log writer.
/// \details
/// Reads all bytes from standard input and appends them to the selected log file.
/// The primary path is tried first. If it cannot be opened or created, the backup
/// path is tried when provided.
/// \param argc Argument count.
/// \param argv Argument values.
/// \return Process exit code.
// ReSharper disable once IdentifierTypo
int wmain(int argc, wchar_t* argv[]) // NOLINT(misc-use-internal-linkage)
{
if(argc < 2 || argv[1] == nullptr || argv[1][0] == L'\0')
return 1; // Missing/invalid primary log file path argument
const std::wstring primaryPath = normalizedPath(argv[1]);
const std::wstring backupPath =
(argc >= 3 && argv[2] != nullptr && argv[2][0] != L'\0') ? normalizedPath(argv[2]) : std::wstring();
if(endsWithSlash(primaryPath))
return 2; // Primary log path is a directory path
if(!backupPath.empty() && endsWithSlash(backupPath))
return 3; // Backup log path is a directory path
const HANDLE stdIn = ::GetStdHandle(STD_INPUT_HANDLE);
if(stdIn == INVALID_HANDLE_VALUE || stdIn == nullptr)
return 4; // Missing/invalid STDIN handle
HANDLE logFile = INVALID_HANDLE_VALUE;
constexpr DWORD bufSize = 64u * 1024u; // 64 KiB
char buffer[bufSize]{};
while(true) {
DWORD bytesRead = 0;
const BOOL readSuccess = ::ReadFile(stdIn, buffer, bufSize, &bytesRead, nullptr);
if(!readSuccess) {
const DWORD error = ::GetLastError();
if(error == ERROR_BROKEN_PIPE || error == ERROR_HANDLE_EOF)
break; // Normal termination: parent closed/crashed and pipe ended.
if(logFile != INVALID_HANDLE_VALUE)
::CloseHandle(logFile);
return 5; // Read failed
}
if(bytesRead == 0)
break; // EOF (End of File) i.e. Main application closed
if(logFile == INVALID_HANDLE_VALUE) {
logFile = openAppendFileWithParentDir(primaryPath);
if(logFile == INVALID_HANDLE_VALUE && !backupPath.empty()) {
logFile = openAppendFileWithParentDir(backupPath);
if(logFile == INVALID_HANDLE_VALUE)
return 6; // Failed to open/create both primary and backup
}
else if(logFile == INVALID_HANDLE_VALUE) {
return 7; // Failed to open/create primary, no backup provided
}
}
DWORD remains = bytesRead;
DWORD offset = 0;
int noProgressTries = 0;
while(remains > 0) {
DWORD written = 0;
const BOOL writeSuccess = ::WriteFile(logFile, buffer + offset, remains, &written, nullptr);
if(!writeSuccess) {
::CloseHandle(logFile);
return 8; // Write failed
}
if(written == 0) {
if(++noProgressTries >= 16) {
::CloseHandle(logFile);
return 9; // No progress after repeated tries
}
::SwitchToThread(); // brief yield
continue;
}
noProgressTries = 0;
offset += written;
remains -= written;
}
}
if(logFile != INVALID_HANDLE_VALUE) {
::FlushFileBuffers(logFile);
::CloseHandle(logFile);
}
return 0; // Normal shutdown
}
