Moodycamel Queue

File: concurrentqueue.h

License: BSD 2-Clause License or Boost Software License 1.0.

The project uses moodycamel::ConcurrentQueue as a third-party, header-only queue for safely transferring data between threads with low synchronization overhead. Only concurrentqueue.h is included; the optional blocking queue and semaphore headers are not used. The queue supports multiple producers and consumers, token-based operations, bulk operations, preallocation, and non-allocating try_enqueue operations. It is lock-free but does not guarantee a strict global order between independent producers, is not sequentially consistent, and is not NUMA-aware. Producer and consumer tokens must not be used concurrently by multiple threads, size_approx() must not be treated as an exact value, and the queue must remain alive until all participating threads have stopped using it.

Magic Enum

File: magic_enum.hpp

License: MIT License.

The project uses magic_enum as a third-party, header-only library for enum reflection and conversion. It provides utilities such as enum_name, enum_cast, enum_values, enum_entries, and enum_count, removing the need for manually maintained enum-to-string tables and repetitive conversion code. It is primarily used for logging, diagnostics, configuration parsing, validation, and developer-facing tooling. The library requires a supported compiler because it relies on compiler-specific function-signature information, and it cannot reflect forward-declared enums. By default, reflected enum values must fall within the range -128 to 127, although this range and individual enum behaviour can be customised.
