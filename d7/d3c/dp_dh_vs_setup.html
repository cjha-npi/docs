Browsing Database Location

The folder location used for browsing database and IntelliSense files. This folder can become very large, often several GB. By default, Visual Studio stores these files in the .vs folder inside the solution folder, which can make the solution folder unnecessarily large and make cleanup tedious. To avoid this, use a separate cache location outside the solution folder. The preferred folder name is VS_Caches.

  • VS 2022: Tools > Options... > Text Editor > C/C++ > Advanced > Browsing Database Fallback
    • Always Use Fallback Location: True
    • Do Not Warn If Fallback Location Used: True
    • Fallback Location: G:\VS_Caches
  • VS 2026: Tools > Options... > Languages > C/C++ > Intellisense > Browsing & navigation > Location
    • Always use the specified custom location for the browsing database: Enabled
    • Custom location for browsing database files: G:\VS_Caches
Note
  • The option can be found by searching for browsing database in the Tools > Options... window.
  • The option Do Not Warn If Fallback Location Used is not available in VS 2026. Instead, when the custom location is used for the first time, a popup appears with a Do not prompt again checkbox. Enable this checkbox to prevent the popup from appearing again. The same popup is also available in VS 2022.
Warning
Visual Studio expects the parent folder of VS_Caches to exist. For example, if the cache location is G:\Bla\VS_Caches, then G:\Bla must already exist. Visual Studio can recreate the VS_Caches folder itself, but it does not create the missing parent folder. If the parent folder is missing, the browsing database and IntelliSense may stop working.

Backup Solution Code on Save

The Backup_Sol_Code_On_Save Visual Commander extension automatically creates a filtered mirror of the Visual Studio solution containing a document whenever that document is saved.

The extension listens for Visual Studio's DocumentSaved event, determines the containing solution directory, and then:

  • Accepts solutions only under F:\Core\, F:\Demo\, and F:\Eval\.
  • Debounces repeated saves from the same project.
  • Queues each project only once.
  • Processes queued projects sequentially.
  • Uses a named Windows mutex to prevent overlapping copies across Visual Studio instances.
  • Launches D:\ToolBox\BackupSolCode\BackupSolCode.cmd without blocking the Visual Studio interface.

The D:\ToolBox\BackupSolCode\BackupSolCode.cmd Robocopy script:

  • Executes only for project folders under F:\Core\, F:\Demo\, and F:\Eval\.
  • Preserves the complete directory structure, so F:\Eval\A\B\C\ is mirrored to E:\Eval\A\B\C\.
  • Copies only:
    • Code files: *.h, *.hpp, *.c, and *.cpp
    • Image files: *.png, *.svg, *.jpg, and *.jpeg
    • Font files: *.ttf and *.otf
    • Other files: *.ui, *.qrc, *.md, *.ico, *.rc, and *.ini
  • Deletes destination files that no longer exist in the source.
  • Does not delete _git folder in destination since it is managed by Git Pre-Push Hook.
  • Deletes empty destination folders.
  • Writes the copy log to D:\ToolBox\BackupSolCode\BackupSolCode.log.
Note
This and Git Pre-Push Hook uses the same basic copying filter rules for Robocopy, so a change in one would mean that the other should be changed similarly.

Installation

Save the following script as D:\ToolBox\BackupSolCode\BackupSolCode.cmd:

@echo off
setlocal EnableExtensions DisableDelayedExpansion
set "sourceRoot=F:\"
set "destinationRoot=E:\"
set "source=%~f1"
set "logDir=D:\ToolBox\BackupSolCode"
set "logFile=%logDir%\BackupSolCode.log"
set "oldLogFile=%logDir%\BackupSolCode.old.log"
set "maxLogSize=20480"
if not exist "%logDir%\" md "%logDir%" >nul 2>&1
rem Validate the supplied solution directory.
if not defined source exit /b 2
if not exist "%source%\" exit /b 3
if /I "%source%"=="%sourceRoot%" exit /b 4
if /I not "%source:~0,3%"=="%sourceRoot%" exit /b 0
rem The source must be below a category root, not the category root itself.
if /I "%source%"=="F:\Core" exit /b 4
if /I "%source%"=="F:\Demo" exit /b 4
if /I "%source%"=="F:\Eval" exit /b 4
rem Accept solutions only under F:\Core\, F:\Demo\, or F:\Eval\.
set "sourceWithSlash=%source%\"
if /I "%sourceWithSlash:~0,8%"=="F:\Core\" goto SourceAllowed
if /I "%sourceWithSlash:~0,8%"=="F:\Demo\" goto SourceAllowed
if /I "%sourceWithSlash:~0,8%"=="F:\Eval\" goto SourceAllowed
exit /b 0
:SourceAllowed
rem Preserve the complete path below F:\.
rem F:\Eval\A\B\Sol becomes E:\Eval\A\B\Sol.
set "destination=%destinationRoot%%source:~3%"
robocopy "%source%" "%destination%" ^
*.h *.hpp *.c *.cpp *.ui *.qrc *.md *.png *.ico ^
*.svg *.jpg *.jpeg *.ttf *.otf *.rc *.ini ^
/S /PURGE /R:1 /W:1 /XJ ^
/XD ".*" "_git" "x64" "x86" "bin" "obj" "out" "build" ^
"_ReSharper.Caches" "GeneratedFiles" "Debug" "Release" ^
/XF ".*" "*.sln" "*.vcxproj" "*.vcxproj.filters" "*.vcxproj.user" ^
/NFL /NDL /NJH /NJS /NP >nul
set "result=%errorlevel%"
rem Remove destination directories that became empty after filtering,
rem source deletion, or source directory removal.
rem Do not delete the _git directory because it is maintained by the Git pre-push hook.
if %result% LSS 8 (
if exist "%destination%\" (
for /F "delims=" %%D in (
'dir "%destination%" /AD /B /S 2^>nul ^| sort /R'
) do (
if /I not "%%D"=="%destination%\_git" (
echo(%%D| findstr /I /B /C:"%destination%\_git\" >nul
if errorlevel 1 rd "%%D" 2>nul
)
)
rd "%destination%" 2>nul
)
)
call :RotateLog
>>"%logFile%" echo [%date% %time%] Result %result%: "%source%" to "%destination%"
rem Robocopy return codes from 0 through 7 are successful or informational.
if %result% GEQ 8 exit /b %result%
exit /b 0
rem Rotate the current log before writing when it is already at least 20 KiB.
:RotateLog
if not exist "%logFile%" exit /b 0
for %%F in ("%logFile%") do (
if %%~zF LSS %maxLogSize% exit /b 0
)
rem Keep only one previous log file.
del /Q "%oldLogFile%" >nul 2>&1
move /Y "%logFile%" "%oldLogFile%" >nul 2>&1
exit /b 0

Install the Visual Commander extension by Sergey Vlasov in Visual Studio. Then open Extensions > VCmd > Extensions..., click Add, and create an extension named Backup_Sol_Code_On_Save using the C# v4.0 language. Paste the following code:

public class E : VisualCommanderExt.IExtension
{
public void SetSite(EnvDTE80.DTE2 DTE, Microsoft.VisualStudio.Shell.Package package)
{
dte = DTE;
events = DTE.Events;
documentEvents = events.DocumentEvents;
documentEvents.DocumentSaved += OnDocumentSaved;
lock (syncRoot)
{
stopping = false;
pendingSolutions.Clear();
}
workerThread = new System.Threading.Thread(WorkerLoop);
workerThread.IsBackground = true;
workerThread.Name = "Backup Solution Code";
workerThread.Start();
}
public void Close()
{
if (documentEvents != null)
documentEvents.DocumentSaved -= OnDocumentSaved;
lock (syncRoot)
{
stopping = true;
}
workEvent.Set();
// Do not hold Visual Studio shutdown indefinitely if Robocopy is active.
if (workerThread != null)
workerThread.Join(2000);
workerThread = null;
documentEvents = null;
events = null;
dte = null;
}
private void OnDocumentSaved(EnvDTE.Document document)
{
try
{
if (document == null ||
string.IsNullOrEmpty(document.FullName) ||
dte == null ||
dte.Solution == null ||
string.IsNullOrEmpty(dte.Solution.FullName))
{
return;
}
string solutionDir =
System.IO.Path.GetDirectoryName(dte.Solution.FullName);
if (string.IsNullOrEmpty(solutionDir))
return;
solutionDir = System.IO.Path
.GetFullPath(solutionDir)
.TrimEnd('\\', '/');
if (!IsAllowedSolutionDirectory(solutionDir))
return;
string documentPath = System.IO.Path
.GetFullPath(document.FullName);
// Ignore documents located outside the current solution directory.
// This prevents saving an unrelated external file from triggering
// a copy of the currently open solution.
if (!IsPathInsideDirectory(documentPath, solutionDir))
return;
lock (syncRoot)
{
if (stopping)
return;
// Updating the time replaces any earlier pending save for the
// same solution and restarts that solution's debounce interval.
pendingSolutions[solutionDir] =
System.DateTime.UtcNow;
}
workEvent.Set();
}
catch (System.Exception)
{
// Saving the document must never be disrupted by backup failures.
}
}
private void WorkerLoop()
{
while (true)
{
string solutionDir = null;
int waitMilliseconds =
System.Threading.Timeout.Infinite;
lock (syncRoot)
{
if (stopping)
return;
System.DateTime now = System.DateTime.UtcNow;
foreach (
System.Collections.Generic.KeyValuePair<
string,
System.DateTime> item in pendingSolutions)
{
double remaining =
debounceMilliseconds -
(now - item.Value).TotalMilliseconds;
if (remaining <= 0.0)
{
solutionDir = item.Key;
break;
}
int candidateWait =
(int)System.Math.Ceiling(remaining);
if (waitMilliseconds ==
System.Threading.Timeout.Infinite ||
candidateWait < waitMilliseconds)
{
waitMilliseconds = candidateWait;
}
}
if (solutionDir != null)
pendingSolutions.Remove(solutionDir);
}
if (solutionDir == null)
{
workEvent.WaitOne(waitMilliseconds);
continue;
}
RunSolutionCopy(solutionDir);
}
}
private void RunSolutionCopy(string solutionDir)
{
try
{
using (System.Threading.Mutex copyMutex =
new System.Threading.Mutex(false, copyMutexName))
{
bool ownsMutex = false;
try
{
// Poll instead of waiting indefinitely so extension
// shutdown can still be noticed.
while (!IsStopping())
{
try
{
ownsMutex =
copyMutex.WaitOne(mutexPollMilliseconds);
}
catch (System.Threading.AbandonedMutexException)
{
// The previous owning process terminated. This
// thread now owns the mutex and may continue.
ownsMutex = true;
}
if (ownsMutex)
break;
}
if (!ownsMutex || IsStopping())
return;
RunScript(solutionDir);
}
finally
{
if (ownsMutex)
{
try
{
copyMutex.ReleaseMutex();
}
catch (System.ApplicationException)
{
}
}
}
}
}
catch (System.Exception)
{
// Failures must not terminate the worker or affect Visual Studio.
}
}
private static void RunScript(string solutionDir)
{
string commandProcessor =
System.Environment.GetEnvironmentVariable("ComSpec");
if (string.IsNullOrEmpty(commandProcessor))
commandProcessor = "cmd.exe";
System.Diagnostics.ProcessStartInfo startInfo =
new System.Diagnostics.ProcessStartInfo();
startInfo.FileName = commandProcessor;
startInfo.Arguments =
"/d /s /c \"\"" +
scriptPath +
"\" \"" +
solutionDir +
"\"\"";
startInfo.UseShellExecute = false;
startInfo.CreateNoWindow = true;
startInfo.WindowStyle =
System.Diagnostics.ProcessWindowStyle.Hidden;
using (System.Diagnostics.Process process =
System.Diagnostics.Process.Start(startInfo))
{
if (process != null)
process.WaitForExit();
}
}
private static bool IsPathInsideDirectory(
string path,
string directory)
{
string fullPath = System.IO.Path
.GetFullPath(path);
string directoryWithSlash = System.IO.Path
.GetFullPath(directory)
.TrimEnd('\\', '/') + "\\";
return fullPath.StartsWith(
directoryWithSlash,
System.StringComparison.OrdinalIgnoreCase);
}
private static bool IsAllowedSolutionDirectory(string solutionDir)
{
string normalizedSolutionDir =
solutionDir.TrimEnd('\\', '/');
string solutionDirWithSlash =
normalizedSolutionDir + "\\";
for (int index = 0;
index < allowedRoots.Length;
++index)
{
string normalizedRoot =
allowedRoots[index].TrimEnd('\\', '/');
// The solution must be below the category root, not the root itself.
if (!normalizedSolutionDir.Equals(
normalizedRoot,
System.StringComparison.OrdinalIgnoreCase) &&
solutionDirWithSlash.StartsWith(
allowedRoots[index],
System.StringComparison.OrdinalIgnoreCase))
{
return true;
}
}
return false;
}
private bool IsStopping()
{
lock (syncRoot)
{
return stopping;
}
}
private const int debounceMilliseconds = 1500;
private const int mutexPollMilliseconds = 250;
private const string copyMutexName =
@"Local\CJ.BackupSolutionCode.Robocopy";
private const string scriptPath =
@"D:\ToolBox\BackupSolCode\BackupSolCode.cmd";
private static readonly string[] allowedRoots =
new string[]
{
@"F:\Core\",
@"F:\Demo\",
@"F:\Eval\"
};
private readonly object syncRoot = new object();
private readonly System.Collections.Generic.Dictionary<
string,
System.DateTime> pendingSolutions =
new System.Collections.Generic.Dictionary<
string,
System.DateTime>(
System.StringComparer.OrdinalIgnoreCase);
private readonly System.Threading.AutoResetEvent workEvent =
new System.Threading.AutoResetEvent(false);
private EnvDTE80.DTE2 dte;
private EnvDTE.Events events;
private EnvDTE.DocumentEvents documentEvents;
private System.Threading.Thread workerThread;
private bool stopping;
}

BUG: Sophos DLL

BUG
Visual Studio : std::system_error due to Sophos Endpoint Agent

The Sophos Endpoint Agent may inject SophosED.dll into a process started under the Visual Studio debugger. In the observed case, SophosED.dll throws and catches std::system_error internally. Visual Studio reports this as a first-chance exception, so the Debug Output window may show messages similar to this:

Exception thrown at 0x00007FFFB5691B6A in <project name>.exe: Microsoft C++ exception: std::system_error at memory location 0x000000F4F98FE950.
Exception thrown at 0x00007FFFB5691B6A in <project name>.exe: Microsoft C++ exception: std::system_error at memory location 0x000000F4F98FEA80.
Exception thrown at 0x00007FFFB5691B6A in <project name>.exe: Microsoft C++ exception: std::system_error at memory location 0x000000F4F98FE9F0.

This was observed three times during startup. If the application continues normally, there is no Unhandled exception, and the process exits with code 0, this is debugger noise and can be ignored.

The messages can be hidden from the Visual Studio Output window, but doing so hides all exception messages in that window. A better fix is to add a narrow Sophos exclusion for the affected development/debug output folder, if that is allowed by the system administrator.
