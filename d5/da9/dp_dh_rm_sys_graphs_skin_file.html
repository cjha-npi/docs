; Description
; =============================================================================
; CJ_SysGraphs is a Rainmeter skin that displays CPU and RAM activity in the
; empty area of the Windows taskbar. It is designed for horizontal taskbars and
; automatically positions itself between the taskbar icons and the system tray.
;
; The skin shows a CPU usage histogram, an optional RAM usage line, and one bar
; per logical CPU processor/thread. CPU core bars are generated by
; CJ_SysGraphs_GenCpuBars.lua and included through CJ_SysGraphs_CpuBars.inc, so
; the layout can adapt to the processor count of the current system.
;
; CJ_SysGraphs.dll is used to read the usable taskbar area. The skin then
; calculates its own position, width, graph size, CPU bar size, and spacing from
; the available taskbar space. If the preferred CPU bar width does not fit, the
; actual bar width is reduced while keeping the graph visible when possible.
;
; Hover and double-click interactions can temporarily show or persist graph and
; CPU bar details. Mouse scrolling over the graph text changes the skin update
; interval, while scrolling over the CPU bar area changes the preferred CPU bar
; width. Scrolling over CPU core labels changes the averaging window used by the
; CPU tick markers.
;
; User-saved values are stored in CJ_SysGraphs_Stored.inc. Stored values are
; validated on load and corrected when needed. Theme-dependent colors are selected
; automatically from the Windows light/dark app theme setting.
; =============================================================================
; =============================================================================
; IMPORTANT NOTES
; =============================================================================
; - On load/refresh all Measures (except Disabled) are executed in sequence,
; regardless of their UpdateDivider values.
; - Meters are updated after all Measures during an update cycle.
; - UpdateDivider=-1 means the Measure/Meter will be updated only once.
; - A Measure value is immediately updated on its update and can be referred
; inside the same measure or any later measures.
; - A variable set using [!SetVariable SomeVar "..."] will only show
; the updated value after the measure that changed it and not inside the same
; measure.
; - Rainmeter section OnRefreshAction is executed at the end of the load/refresh.
; (Sometimes it is delayed by a few update cycles if update cycle is small e.g. 100ms).
; - A Meter with UpdateDivider=-1, will be updated only once but it can be
; delayed by a few update cycles (if the update cycle is small e.g. 100ms),
; but any value from it e.g. [SomeMeter:W] can be used by another Measure
; before the Meters update runs because the Rainmeter can already calculate
; or know the meter’s geometry.
; =============================================================================
; Requires Rainmeter 4.5+ because #CURRENTCONFIGZPOS# is used.
; =============================================================================

; =============================================================================
; Skin Position and Z-Position Restore
; =============================================================================
; Keeps the skin locked to the calculated taskbar position and restores its
; expected Z-position if either value is changed externally or by the user.
;
; NOTE:
; IfConditionMode=1 is required because the corrective action must run on every
; update while the condition remains true. With the default condition mode,
; IfTrueAction only runs when the condition changes from false to true. That is
; not enough while the user is dragging the skin, because the incorrect position
; can remain true for multiple update cycles.
;
; NOTE:
; Do not enforce position or Z-position through OnUpdateAction, for example:
; OnUpdateAction=[!Move [XCoord] [YCoord]]
; Doing that runs the bang every update, even when nothing changed. It can make
; Rainmeter's Manage UI flicker widgets such as comboboxes, spinboxes, and
; dropdowns. The trigger measures below only run their actions when the current
; state differs from the required state.
; Moves the skin back to the calculated taskbar position when needed.
; This keeps the skin aligned after monitor/taskbar changes or accidental user
; movement.
